# SQLite в МедАрхиве: решение о прекращении использования

**Статус:** перенос данных не требуется  
**Дата решения:** 2026-11-11

## Решение

SQLite использовалась только в первоначальном прототипе. По подтверждению владельца проекта, в базе прототипа нет данных, которые необходимо сохранять или переносить.

Целевая версия МедАрхива разрабатывается непосредственно на PostgreSQL. Отдельная процедура миграции данных SQLite → PostgreSQL, staging-слой, таблицы соответствий legacy ID и перенос исторических записей не входят в объём работ.

## Что это означает для разработки

- PostgreSQL — единственная СУБД целевой версии и единственный источник истины.
- Существующий SQLite-адаптер не развивается и не используется целевой версией приложения.
- Схема PostgreSQL создаётся и изменяется через Alembic.
- Для разработки и тестирования используются чистая PostgreSQL-БД и специально подготовленные тестовые данные.
- Старый SQLite-код остаётся в истории Git как часть прототипа; удалять его следует после проверки зависимостей и только отдельным изменением.
- Не переносить автоматически старые статусы, тестовые записи или предположительную историю из SQLite.

## Что сохраняется из старого прототипа

Повторно используются только проверенные части приложения, не зависящие от SQLite: интерфейс, шаблоны, полезные компоненты авторизации и бизнес-логики. Их пригодность определяется при аудите кода. Слой хранения и связанные с ним запросы переписываются под PostgreSQL.

## Отличие от миграций Alembic

Alembic нужен и при отсутствии переноса данных. Он управляет версиями **структуры** PostgreSQL: создаёт таблицы, индексы, ограничения и последующие изменения схемы. Это не импорт данных из SQLite.

## Историческая справка

Предыдущий план переноса SQLite → PostgreSQL признан неактуальным и заменён настоящим решением. Его не следует использовать как инструкцию к выполнению работ.
