# Дизайн: «Мои открытые коробки» на /packing + сообщение о дубликате карты

**Дата:** 2026-08-28
**Статус:** утверждён (destorrr, 10:45)
**Связано:** чек-лист Этапа 1, п. 1.4; коммит `731d3f8` (активная коробка в БД)

---

## Проблемы

1. **Баг п.1.4:** повторное сканирование «Иванов Иван Иванович» не добавляет карту повторно (✅), но сообщение «карта уже в этой коробке» не показывается (❌).
   - Root cause: `BoxRepositoryImpl.add_card()` при дубликате молча `return`; `BoxService.scan_card()` не узнаёт о дубликате, роутер рендерит фрагмент без ошибки.
2. **Фича:** на `/packing` пользователь должен видеть **все свои открытые коробки** и иметь возможность «зайти» в любую (продолжить упаковку).

## Решения

### Хранение выбора активной коробки
- Колонка **`users.active_box_id INTEGER REFERENCES boxes(id)`** (nullable) — выбор персистентный, переживает рестарт/логаут/смену браузера (согласуется с `731d3f8`).
- Миграция идемпотентная: колонка в `CREATE TABLE users` + `ALTER TABLE` для существующих БД (через `PRAGMA table_info`).

### Сообщение о дубликате
- `BoxRepositoryImpl.add_card()` → возвращает `bool` (True — добавлена, False — дубликат).
- `BoxService.scan_card()` → при дубликате бросает **`DuplicateCardError`** (статус карты и движение НЕ меняются).
- Роутер ловит исключение → flash «Карта «…» уже в этой коробке» во фрагменте; список карт и коробок сохраняется.

### Страница /packing
- GET `/packing` — активная коробка + её карты + блок **«📂 Мои открытые коробки»** (все `packing`-коробки пользователя: номер, кол-во карт, дата).
- **«Перейти»** — `POST /packing/open-box` (новый) → `select_box(box_id, user_id)` с проверкой «своя + открытая» → фрагмент с выбранной коробкой.
- **«🏁 Закрыть коробку»** — только для активной коробки (как сейчас); закрытие из списка НЕ предусмотрено.
- **«➕ Новая коробка»** — видна всегда.
- Все htmx-ответы (scan/remove/open) включают `open_boxes`, чтобы список обновлялся без перезагрузки.

### Закрытие и выбор
- `close_box(box_id, user_id)` — если закрыли активную коробку → `users.active_box_id = NULL` (остальные открытые остаются в списке).
- `create_box` → активная = новая коробка.
- `get_active_for_user()` — приоритет `active_box_id` (если коробка ещё `packing`), fallback — последняя `packing` (обратная совместимость со старыми данными).

## Компоненты
- `migrations.py` — схема + инкрементальный ALTER.
- `domain/models.py` — `User.active_box_id: int | None = None`.
- `repositories.py` (BoxRepositoryImpl) — `get_active_for_user` (обновлён), `set_active_box`, `list_open_for_user`, `add_card → bool`; UserRepositoryImpl/dependencies прокидывают `active_box_id`.
- `box_service.py` — `DuplicateCardError`, `select_box`, `list_open_boxes`, обновлённые `create_box`/`scan_card`/`close_box`.
- `routers/packing.py` — `open-box`, `close-box` с опциональным `box_id` (передаёт `user_id`), контекст `open_boxes`/`active_box_id` во всех ответах.
- `packing_fragment.html` — блок «Мои открытые коробки».

## UI (утверждённый макет)
- Активная коробка: номер · N карт · метка «● активная»; кнопка «🏁 Закрыть коробку» внизу.
- Список: строки «номер · N карт · дата»; у неактивных — кнопка **«Перейти»**; у активной — только метка.
- «➕ Новая коробка» — всегда видна.

## Error handling
- Дубликат карты → `DuplicateCardError` → flash.
- «Перейти» на чужую/закрытую коробку → `ValueError` → flash, активная не меняется.

## Testing strategy
- **Service:** дубликат → `raises DuplicateCardError` (обновить существующий тест); `select_box` своя/чужая/закрытая; закрытие активной → `active_box_id=NULL`; `create_box` → выбор установлен; `list_open_boxes` — только `packing`.
- **Router:** повторный скан → «уже в этой коробке», карт 1; GET `/packing` при двух открытых коробках → обе видны; `open-box` переключает активную (БД + фрагмент); закрытие активной сбрасывает выбор.
- **Миграция:** после `init()` в `PRAGMA table_info(users)` есть `active_box_id`.

## Scope boundaries (НЕ делаем)
- Не трогаем /transfer, receive, остальные роутеры.
- «Карта уже в другой коробке» — вне scope (отдельная задача).
- Поиск/пагинация по коробкам — вне scope.
