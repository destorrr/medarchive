# Дизайн: ошибка «Подтвердить приёмку» — вариант C (htmx)

Дата: 2026-08-31
Статус: утверждён (макет `receive_confirm_error_mockup.html`, вариант C выбран пользователем)

## Проблема

При подтверждении приёмки коробки, которая не в статусе `in_transit` (например, `ready` или уже `received`), сервер возвращает `HTMLResponse(..., status_code=400)`. При обычном POST-сабмите браузер рендерит голое тело ответа на URL `/receive/confirm` — пользователь «выпадает» со страницы без контекста.

## Решение (вариант C)

1. **Форма подтверждения в scan-фрагменте** — снова htmx: `hx-post="/receive/confirm" hx-target="#scan-result"` (вставка ответа в блок скана, страница не перезагружается).

2. **`confirm_receive`:**
   - **Успех** — `Response(status_code=200, headers={"HX-Redirect": f"/placement?box_id={box_id}"})` — htmx выполняет полный переход на страницу размещения.
   - **Ошибка** — `HTMLResponse(f'<div class="flash ...">сообщение</div>', status_code=200)` — htmx вставляет фрагмент прямо под кнопкой «Подтвердить приёмку», состав коробки остаётся на экране.

3. **Русские статусы в сообщениях об ошибках** — в `receive_service.py` заменить сырые значения enum на подписи из нового словаря `BOX_STATUS_LABELS`:
   - `receive_box`: «Коробка должна быть в статусе 'В пути', сейчас 'Готова'»
   - `place_box`: «Коробка должна быть в статусе 'Принята', сейчас 'В пути'»

## Новый словарь

`BOX_STATUS_LABELS: dict[BoxStatus, str]` в `src/medarchive/domain/statuses.py`:

| Статус | Подпись |
|--------|---------|
| packing | Упаковывается |
| ready | Готова |
| in_transit | В пути |
| received | Принята |
| placed | Размещена |
| lost | Потеряна |

## Вне скоупа

- `shipment_service.py`, `return_service.py` и другие сообщения со статусами — НЕ трогаем (отдельная задача при необходимости)
- `/placement` (confirm_placement — обычный POST + 303) — НЕ трогаем
- Логика приёмки, статусы, переходы — без изменений
