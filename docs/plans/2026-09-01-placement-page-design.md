# Дизайн: /placement — вариант A (htmx-флоу без перезагрузок)

Дата: 2026-09-01
Проект: МедАрхив
Статус: утверждён пользователем (интерактивный макет `placement_redesign_mockup.html` одобрен; выбор полки — каскад «Секция → Полка»)

## Проблема

Приёмочное тестирование Этапа 1, п.1.11 («/placement → выбери коробку → полка A-1 → Разместить → placed»).
Функционально п.1.11 работает (коробка размещается, исчезает из списка), но зафиксированы дефекты UI:

1. **Дизайн не в общем стиле** — страница на старом шаблоне (голый h1 + карточка), без единого стиля
   таблиц/бейджей/флешей, принятого в `/receive` и `/transfer`.
2. **Нет интерактивности** — каждый шаг (выбор коробки → выбор полки → подтверждение) — полная
   перезагрузка страницы.
3. **Голое пустое состояние** — после размещения всех коробок остаётся строка «Выберите коробку
   для размещения:» и ничего больше.

## Цель

Привести `/placement` к визуальному стандарту `/receive`/`/transfer` (карточки `.card`, таблицы с
padding 8px и разделителями, флеши) и сделать флоу размещения интерактивным через htmx — без
перезагрузок страницы.

## Утверждённый макет

`~/.openclaw/canvas/documents/medarchive/placement_redesign_mockup.html`
(интерактивный: клик «Разместить» → панель инлайн; подтверждение → строка исчезает + флеш;
пустое состояние «🎉 Все коробки размещены»; выбор полки — каскад «Секция → Полка»).

## Решения

### 1. Структура страницы (placement.html)

- `h1` «📍 Размещение коробок» — как на других страницах.
- Включение partial `placement_area.html` (флеш + список/пустое состояние) — единый блок,
  который перерисовывается после каждого размещения.

### 2. Partial `placement_area.html` (флеш + список)

- Опциональный флеш сверху (success/error), стили `.flash-success` / `.flash-error` — новые классы
  в `base.html` (существующий `.flash` не трогаем, это warning-вариант).
- **Если есть принятые коробки** — карточка «📦 Ожидают размещения (N)» с таблицей:

  | # | Коробка | Откуда | Принята | Карт | Действие |
  |---|---------|--------|---------|------|----------|
  | 1 | B-011 | Филиал 2 | 2026-09-01 10:12 | 3 | [Разместить] |

  - «Откуда» — `branch_name` (JOIN branches по `origin_branch_id`).
  - «Принята» — `shipments.received_at` (уже пишется при приёмке, миграции НЕ нужны).
  - «Карт» — COUNT из `box_cards`.
  - Номер коробки — `font-weight: 600`, колонка `#` — `#888` (как в `/packing`).
- **Если коробок нет** — карточка пустого состояния: «🎉 Все коробки размещены», подпись
  «Новых коробок, ожидающих размещения, нет», хинт «Коробки появляются здесь после приёмки
  на странице „Приёмка“».
- Каждая строка:
  - кнопка «Разместить» — `hx-get="/placement/select?box_id=N"` с `hx-target="#panel-row-N"`,
    `hx-swap="innerHTML"`, и `hx-on::after-request` (скрыть строку `#row-N`, показать панель `#panel-row-N`);
  - под строкой — скрытый `<tr id="panel-row-N">` — контейнер панели размещения.
- Если пришёл `selected_box_id` (переход с `/receive` через HX-Redirect `?box_id=N`) — панель
  для этой коробки рендерится сервером сразу (инлайн, видимая), строка скрыта: переход
  «принял → размещаю» не теряет контекст.

### 3. Partial `placement_panel.html` (фрагмент GET /placement/select)

- Шапка: chip `📦 B-011` + мета «N карт · принята …».
- **Каскад «Секция → Полка»**:
  - select «Секция» — все секции (`value` = id секции);
  - select «Полка» — изначально `disabled`, «— Сначала выберите секцию —»;
  - JS-фильтр: данные секций→полок передаются `{{ sections | tojson }}` в `<script>` внутри
    фрагмента (htmx исполняет скрипты подменяемого контента); при выборе секции полки
    наполняются (id + name [+ qr]);
  - кнопка «Разместить» `disabled`, пока не выбраны секция И полка.
- Скрытый `input[name=box_id]`.
- Кнопки:
  - «Разместить» — `hx-post="/placement/confirm"` `hx-target="#placement-area"` `hx-swap="outerHTML"`;
  - «Отмена» — inline JS: скрыть панель, вернуть строку, очистить контейнер панели.

### 4. Роутер archive.py

- `GET /placement` — логика прежняя; контекст дополняется: `received_boxes` (обогащённые),
  `sections` (дерево секций → полки, как сейчас), `selected_box_id`.
- **НОВЫЙ** `GET /placement/select?box_id=N` → рендер `placement_panel.html` для коробки.
  Ошибки (коробка не найдена / не в статусе `received`) — флеш-фрагмент с текстом.
- `POST /placement/confirm` — бизнес-логика прежняя (`place_box`), НО ответ меняется:
  - успех → `placement_area.html` с success-флешем «✅ Коробка B-011 размещена на полке A-1»
    и обновлённым списком (строка исчезла) — htmx заменяет `#placement-area`, перезагрузки нет;
  - `ValueError` (коробка уже размещена и т.п.) → `placement_area.html` с error-флешем и списком
    без изменений;
  - `shelf_id` отсутствует → error-флеш «Выберите полку» (вместо 422 FastAPI).

### 5. Сервис receive_service.py

- `get_received_boxes` — обогатить запрос:

  ```sql
  SELECT b.*, br.name AS branch_name, s.received_at,
         (SELECT COUNT(*) FROM box_cards bc WHERE bc.box_id = b.id) AS cards_count
  FROM boxes b
  JOIN branches br ON br.id = b.origin_branch_id
  LEFT JOIN shipments s ON s.box_id = b.id AND s.status = 'received'
  WHERE b.status = 'received'
  ORDER BY b.box_number
  ```

- `place_box`:
  - guard: полка с `shelf_id` не найдена → `ValueError("Полка не найдена")` (сейчас — необработанный
    FK-500 при невалидном id);
  - возвращает имя полки (уже выбирает её внутри) — для success-флеша.

### 6. base.html

- Новые классы (не ломают существующее):
  - `.flash-success { background:#e8f5e9; border-color:#66bb6a; color:#2e7d32; }`
  - `.flash-error { background:#fdecea; border-color:#e57373; color:#c0392b; }`

## Вне скоупа

- `/packing`, `/transfer`, `/receive`, `/my-shipments` и другие страницы (принятые пункты Этапа 1 не трогаем).
- Современный редизайн всего приложения (Roboto/Font Awesome/карточки) — отдельный этап после п.1.12.
- Кастомный dropdown из `/transfer` — не нужен (каскад нативных select, нативная доступность).
- Миграции схемы, `received_at` в `boxes`, аудит движений.

## Тестирование

- **service** (`tests/services/test_receive_service.py`):
  - `get_received_boxes` возвращает `branch_name`, `received_at`, `cards_count`;
  - `place_box` возвращает имя полки;
  - `place_box` с несуществующей полкой → `ValueError`.
- **router** (`tests/routers/test_archive.py`):
  - `GET /placement` — «Ожидают размещения», заголовки таблицы, пустое состояние при отсутствии коробок;
  - `GET /placement/select?box_id=N` — панель: селекты «Секция»/«Полка» (полка disabled), hidden `box_id`,
    chip с номером коробки;
  - `GET /placement/select` для несуществующей/не-принятой коробки → флеш-ошибка;
  - `POST /placement/confirm` успех → 200, флеш «размещена на полке», в списке строки больше нет,
    в БД статус `placed`;
  - `POST /placement/confirm` повторно (уже `placed`) → error-флеш, список без изменений;
  - `POST /placement/confirm` без `shelf_id` → error-флеш «Выберите полку»;
  - регресс: приёмка (`/receive*`) не меняется.
- Полный прогон: `pytest -q` — все зелёные, без регрессий.
