# Дизайн: /search — итоговый макет (п.1.12 приёмки)

Дата: 2026-09-05
Проект: МедАрхив
Статус: утверждён пользователем (интерактивный макет `search_final_mockup.html` на canvas, 2026-09-05)

## Проблема

Приёмочное тестирование Этапа 1, п.1.12 («/search по ФИО одной из карт → карта „размещена“, место A-1»).
Функционально поиск работает, но зафиксированы дефекты:

1. **Старый дизайн** — страница вне стиля `/receive`, `/placement`, `/transfer` (голая форма + таблицы,
   статусы сырыми английскими значениями).
2. **Нет интерактивности** — POST-форма с полной перезагрузкой.
3. **Поиск регистрозависим** — SQLite `LIKE '%…%'` не сворачивает регистр кириллицы: «иванов» не находит
   «Иванов».
4. В демо-данных карта числится в нескольких активных коробках (артефакт: guard «карта в другой коробке»
   не реализован) — старый вывод показывал карту строкой на каждую коробку.

## Утверждённый макет

`~/.openclaw/canvas/documents/medarchive/search_final_mockup.html` — вариант C + правило B-1.

## Решения

### 1. Формат результата: одна карта = одна строка (сервис)

`SearchService.search_cards(query)` возвращает **одну запись на карту**:

```
{
  "id": 1, "full_name": "Иванов Иван Иванович", "status": "placed",   # статус КАРТЫ
  "box_number": "B-0011",     # актуальная коробка (или None)
  "box_status": "placed",
  "place": "А / 003",         # раздел/полка актуальной коробки (или None)
  "stale": ["B-0003", "B-0010"]   # прочие активные коробки — ТОЛЬКО номера
}
```

- **Актуальная коробка** выбирается по цепочке переходов статуса карты:
  - `in_box` → коробка `packing`/`ready`; `in_transit` → `in_transit`; `in_archive` → `received`;
  - `placed` и `pending_return` → коробка `placed` (карта физически на полке);
  - при нескольких подходящих — самая свежая по `box_placements.placed_at`, затем по `box_cards.added_at`,
    затем по `box.id` DESC;
  - если подходящей нет — самая свежая активная коробка; если активных нет — `box_number = None`.
- **`stale`** — остальные активные коробки (`removed_at IS NULL`), кроме актуальной: только номера,
  без мест и статусов (правило B-1: остатки — не локации карты).

### 2. Регистронезависимость (кириллица)

SQLite не сворачивает регистр кириллицы ни в `LIKE`, ни в `LOWER()`. Поиск — двухфазный в Python:
1. лёгкая выборка `SELECT id, full_name FROM cards`, фильтр `query.lower() in full_name.lower()`;
2. по найденным id — join-запрос местонахождений (box_cards активные → boxes → box_placements →
   archive_shelves → archive_sections), схлопывание в Python по правилу п.1.
Коробки (`search_boxes`) — тот же приём по `box_number` (единообразно).

`search_boxes` дополнительно возвращает место размещённой коробки (`place`) для колонки «Место».

### 3. Роутер (dashboard.py)

- `GET /search` — страница; опциональный `?query=` (нет-JS фолбэк и прямые ссылки): рендерит
  `search.html` с результатами внутри.
- **НОВЫЙ** `GET /search/results?query=` — htmx-фрагмент: рендерит только блок результатов
  (`search_fragment.html`) — им живой поиск обновляет область `#search-results`.
- Старый `POST /search` — legacy 303-редирект на `GET /search?query=…` (совместимость).
- Подсветка совпадений `<mark>` — серверная, экранированная (функция в роутере: разбивает текст по
  первому регистронезависимому вхождению и возвращает `Markup`).
- Статусы → русские подписи через `CARD_STATUS_LABELS`/`BOX_STATUS_LABELS` + классы бейджей из `base.html`.

### 4. Шаблоны (стиль макета)

- `search.html`: `h1` «🔍 Поиск по архиву», карточка-поле ввода (форма GET), подсказка
  «результаты по мере ввода · Esc очистить · поиск без учёта регистра», область `#search-results`;
  **page-level `<style>`** (прецедент — `transfer.html`): классы `.ci*` (карта), `.bi*` (коробка),
  пустые состояния; в конце — скрипт Esc/«✕» (inline, как в макете).
- `search_fragment.html` (partial): «Карты (N)» → список `.ci`:
  - строка: ФИО (с `<mark>`) + бейдж статуса карты;
  - деталь: зелёное место актуальной коробки (или «в коробке B-0107», если места нет; «нет активной
    коробки», если коробки нет);
  - серая строка «не выписана из коробок: B-0003, B-0010», если `stale` непуст;
  - «Коробки (M)» → список `.bi`: номер (с `<mark>`), бейдж статуса, справа «место · N карт»;
  - секции скрываются, если пусты; при пустом результате в целом — карточка «ничего не найдено».
- htmx на поле: `hx-get="/search/results" hx-trigger="input changed delay:350ms, search"
  hx-target="#search-results" hx-swap="innerHTML" name="query"` (скрытый submit не нужен: Enter
  отправляет форму GET целиком).

### 5. Безопасность

- Подсветка — только экранированными сегментами (никаких f-string в HTML).
- Все значения из БД — через Jinja-autoescape.

## Вне скоупа

- QR-идентификация карт (card_number/ДР) — отдельный этап после приёмки.
- Глобальный редизайн приложения — отдельный этап.

## Тестирование

- **service** (`tests/services/test_search_service.py`, переписать):
  - «иванов» строчными находит «Иванов Иван Иванович» (кириллица, регистронезависимо);
  - карта в нескольких коробках → одна запись: актуальная = последняя `placed` по `placed_at`,
    `stale` = остальные номера;
  - одна коробка → `stale = []`, `place` = раздел/полка;
  - карта без коробки → `box_number = None`;
  - `search_boxes("b-0010")` находит «B-0010»; у размещённой коробки есть `place`;
  - регресс `get_card_location` не меняется.
- **router** (`tests/routers/test_search.py`, переписать):
  - `GET /search` → 200, поле поиска;
  - `GET /search?query=иванов` → «Иванов Иван Иванович», бейдж «Размещена», «А / …»;
  - `GET /search/results?query=…` → 200, фрагмент с результатами (без полной страницы);
  - `POST /search` → 303 на `/search?query=…`;
  - пустой результат → «ничего не найдено»;
  - регистронезависимость на уровне роутера.
