# UX-01 — инвентаризация маршрутов и переходов архивного интерфейса

Дата: 2026-11-17  
Ветка: `docs/ux-audit-project`  
Статус: инвентаризация текущего PostgreSQL UI; не целевая схема.

## 1. Основные страницы архива

| Страница | GET | Назначение |
|---|---|---|
| Приёмка | `/receive` | Входящие отправления в архив, состав, сверка, подтверждение, разрешение инцидента |
| Размещение | `/placement` | Внутренние коробки, состав коробок, размещение коробок/отдельных карт на полках, снятие, списание |
| Заявки ЦО | `/requests` | Очередь заявок, состояние карты, извлечение карты из внутренней коробки, подготовка к выдаче, отметка «не найдена», формирование отправления |
| Этикетка коробки | `/boxes/{box_id}/label` | Печать/просмотр QR-этикетки при выполнении проверки области доступа |

## 2. POST-маршруты и результат перехода

| Исходная страница | POST | Результат |
|---|---|---|
| Приёмка | `/receive/confirm` | 303 обратно на `/receive`; подтверждение полного состава |
| Приёмка | `/receive/resolve` | 303 обратно на `/receive`; разрешение инцидента через общий workflow приёмки |
| Размещение | `/placement/new-internal-box` | 303 на `/placement`; создать внутреннюю коробку, опционально из выбранных карт |
| Размещение | `/placement/add-card` | 303 на `/placement`; добавить отдельную карту во внутреннюю коробку |
| Размещение | `/placement/remove-card-from-box` | 303 на `/placement`; извлечь карту из внутренней коробки |
| Размещение | `/placement/box` | 303 на `/placement`; назначить коробке полку |
| Размещение | `/placement/card` | 303 на `/placement`; назначить отдельной карте полку |
| Размещение | `/placement/remove-box` | 303 на `/placement`; снять коробку с полки |
| Размещение | `/placement/remove-card` | 303 на `/placement`; снять карту с полки |
| Размещение | `/placement/write-off-box` | 303 на `/placement`; списать пустую коробку |
| Заявки | `/requests/not-found` | 303 на `/requests`; отметить карту не найденной с пояснением |
| Заявки | `/requests/unpack-card` | 303 на `/requests`; извлечь карту из внутренней коробки |
| Заявки | `/requests/fulfill` | 303 на `/requests`; создать отправление архива → ЦО для выбранных доступных карт |
| ЦО — создание заявки | `/requests/create` | 303 обратно в контекст создания заявки; создать заявку по выбранным картам |

## 3. Фактические переходы в шаблонах

### Размещение

- Операции над составом коробки выполняются inline в строке/карточке коробки: добавить карту, извлечь карту, назначить полку.
- Размещение отдельной карты на полке также выполняется inline в строке карты.
- Снятие коробки/карты с полки выполняется inline в соответствующей таблице.
- QR-этикетка открывается отдельной вкладкой.
- Создание внутренней коробки — отдельная форма в верхней части страницы и отдельная форма для набора отмеченных карт.
- При отсутствии полок интерфейс предлагает перейти в административный раздел для настройки секций/полок.

### Заявки

- Очередь содержит заявки в разных состояниях; выбор к исполнению доступен для новых заявок, когда карта не в коробке и не размещена отдельно на полке.
- Если карта находится во внутренней коробке, строка предлагает действие «Извлечь из коробки»; POST возвращает пользователя в очередь.
- Если карта размещена на полке, строка предлагает переход на `/placement`; фактическое снятие с полки выполняется уже на другой странице.
- Исполнение нескольких заявок объединяется в одну форму с выбором доступных карт и получателем/курьером.
- Отметка «не найдена» выполняется из строки заявки и требует пояснения.
- После POST пользователь возвращается на страницу списка, а не на отдельную карточку заявки.

## 5. Наблюдения для UX-02/UX-04

1. Очередь заявок уже содержит действия над картой и коробкой, но операция снятия с полки уводит в отдельный раздел. Возможность выполнить это действие прямо в очереди требует проверки сценария и согласования.
2. Состояния «карта в коробке» и «карта на полке» дают разные действия в строке заявки; их нужно визуально различать, иначе пользователю сложно понять, почему одна карта готова к выдаче, а другая нет.
3. Создание отправления по заявкам — групповое действие, но отдельные карты сначала должны стать физически доступными. Стоит оценить единый сценарий «подготовить выбранные заявки», не меняя бизнес-правила до согласования.
4. Переход в административный раздел при отсутствии полок — межрольная зависимость рабочего процесса; возможно, требуется диагностическое сообщение/запрос администратору, а не ссылка на чужую операционную задачу.
5. Возврат всех POST на список упрощает поток, но пользователь может потерять контекст конкретной строки/фильтра/прокрутки. Нужно проверить query parameters, flash messages и фокус после обновления.

**Не утверждено:** объединение страниц, изменение переходов, inline-снятие с полки, новые статусы или действия.
