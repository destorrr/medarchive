# UX-05 — проектирование дашбордов и стартовых страниц

**Статус:** ЗАКРЫТ 2026-11-18 по подтверждению владельца продукта. Спецификация дашбордов четырёх ролей, формулы показателей, быстрые действия и целевые переходы согласованы; итоговая перекрёстная проверка выполнена.  
**Рабочая ветка:** `docs/ux-audit-project`  
**Основа:** текущий PostgreSQL dashboard router/template, UX-01 inventory, UX-02 процессы, UX-03 матрица полномочий, согласованный UX-04, D-01…D-18 и P-01…P-08.  
**Граница:** UX-05 определяет назначение стартовой страницы, ролевые сводки, приоритеты очередей, быстрые переходы и состояния блоков. Визуальные wireframes относятся к UX-07; интерактивный прототип — UX-08; реализация — UX-10.

## 1. Цели и принципы

Стартовая страница должна отвечать сотруднику на три вопроса:

1. Что требует моего действия сейчас?
2. Какие рабочие объекты/процессы находятся в моей зоне ответственности?
3. Куда перейти, чтобы выполнить следующее действие?

Принципы проектирования:

- **Сначала работа, потом статистика.** Очереди, требующие действий, выше справочных количеств.
- **Ролевой scope.** Сводки branch, central_office и archive ограничены рабочей областью роли; admin имеет глобальный обзор в рамках D-07.
- **Каждая цифра объяснима.** Для показателя должны быть определены сущность подсчёта, статус, область, момент актуальности и переход к деталям. Если корректный подсчёт не определён, блок не показывается.
- **Без ложных KPI.** Не вводить нормативы, SLA, просрочки, тренды и проценты без утверждённой формулы и источника.
- **Не подменять ёмкость количеством.** Количество карт/коробок на хранении допустимо, процент заполнения архива запрещён без достоверной физической ёмкости (D-12).
- **Не создавать глобальную операционную ленту.** Операционная история показывается в карточках карты, коробки/цикла и отправления; глобальный административный аудит остаётся отдельным экраном admin (D-16).
- **Переход из блока ведёт в согласованный раздел UX-04**, с предустановленным фильтром/вкладкой, если это возможно.
- **Доступность по роли не выводится из наличия ссылки.** Серверная авторизация и object scope обязательны независимо от дашборда.
- **Никаких действий admin от имени операционных ролей.** Стартовая страница admin не содержит обычных кнопок приёмки, передачи, размещения и исполнения заявок (D-07/P-07).

## 2. Аудит текущей стартовой страницы PostgreSQL

Проверены `src/medarchive/routers/postgresql_dashboard.py` и `src/medarchive/templates/dashboard.html` на рабочей ветке.

### 2.1 Текущая реализация

- Один шаблон «Панель управления» используется для всех ролей.
- Универсальный набор из шести карточек: «Карт всего», «В архиве», «В филиалах», «В пути», «Коробок всего», «Открытых заявок».
- Ниже выводятся последние пять движений и ссылка «Открыть журнал» на `/history`.
- В шапке размещена общая ссылка на поиск карты или коробки.
- Состав меню в dashboard router зависит от роли, но содержимое самой панели практически универсально.
- Dashboard router пока допускает `viewer`; в целевой модели эта роль исключена (D-06). UX-05 не меняет legacy ACL и не решает миграцию пользователей.

### 2.2 Проблемы и несоответствия целевой модели

| Наблюдение | Риск/проблема | Целевое направление |
|---|---|---|
| Универсальные показатели для четырёх ролей | Не показывают рабочую задачу конкретной роли; часть карточек для роли всегда равна нулю | Разные ролевые блоки и порядок приоритетов |
| «В архиве» выводится из учётной локации карты | Не означает, что карта физически стоит на полке; D-11 различает учётную локацию и размещение | Разделять «в архиве» и «размещено на полке», если оба числа нужны и имеют корректный источник |
| «Карт всего» и «Коробок всего» | Без видимого определения непонятно, включены ли объекты в пути, и что считается активным циклом/логистической единицей | Определить формулу, область и переход до вывода показателя |
| «Открытых заявок» | Один и тот же показатель не одинаково полезен ролям; статусная выборка и область должны соответствовать владельцу процесса | ЦО видит свои созданные заявки; архив — очередь исполнения |
| «Последние движения» | Дублирует глобальную операционную ленту и ссылку на журнал, что расходится с D-16 | Убрать глобальную ленту; показывать конкретные очереди и ссылки на карточки объектов |
| Общая ссылка «Найти карту или коробку» | Может восприниматься как глобальный поиск, хотя операционные роли ограничены scope | Вести в поиск только своей области; глобальный поиск — только admin |
| Нет быстрых действий по роли | Для старта работы пользователь должен самостоятельно искать нужный раздел | Разрешённые быстрые переходы в разделы/формы |
| Admin видит те же блоки, что операционные роли | Смешивает административный обзор и операционную работу | Отдельная административная стартовая страница |

Текущая страница — источник для аудита, а не целевой образец. В UX-10 нельзя просто добавить/убрать карточки, не исправив семантику данных и scope.

## 3. Целевой каркас стартовой страницы

Предлагаемый порядок блоков:

1. **Контекст:** название рабочего пространства, филиал/ЦО/архив или роль admin.
2. **Требует внимания:** только очереди и состояния, где у текущей роли есть следующее разрешённое действие.
3. **Быстрые действия:** 2–4 наиболее частых разрешённых перехода; не дублировать все пункты меню.
4. **Текущая работа:** короткая сводка по объектам/процессам в области роли.
5. **Недавние объекты:** только если это помогает вернуться к конкретной карточке/отправлению; не глобальная лента событий.
6. **Справочная информация:** необязательные количественные показатели с точной подписью и ссылкой в соответствующий реестр.

Порядок адаптивен: если у роли нет очереди с действием, блок «Требует внимания» показывает нейтральное пустое состояние, а не искусственный KPI.

## 4. Дашборд branch — филиал

### Цель

Помочь сотруднику филиала регистрировать карты, упаковывать их в коробки и отправлять коробки в архив. Входящие отправления и приёмка филиалом в текущий scope не входят.

### Приоритетные блоки

| Приоритет | Блок | Содержание | Переход |
|---|---|---|---|
| 1 | Коробки в работе | Количество активных коробок в филиале и, если достоверно, количество коробок с картами | «Коробки и упаковка» |
| 2 | Карты филиала | Количество карт, находящихся внутри коробок, которые сейчас находятся в работе в данном филиале. Карты в уже отправленных коробках исключаются; при отправке коробки количество карт филиала уменьшается | «Карты» с фильтром по текущему филиалу и нахождению в активной коробке филиала |
| 3 | Быстрые действия | «Создать карту», «Сканировать QR», «Упаковать коробку», «Создать отправление» | Формы/разделы в пределах branch |
| 4 | Исходящие отправления | Отправления филиал → архив, находящиеся в пути; без чужих отправлений | «Отправления» с вкладкой «Исходящие» |
| 5 | Недавно открытые объекты | Опционально: последние карты/коробки/свои отправления, а не события чужой дальнейшей истории | Карточка объекта при сохранении scope |

### Ограничения

- Не показывать заявки ЦО и очередь архива.
- Не показывать глобальную статистику по филиалам, архиву и ЦО.
- После передачи карты в архив не показывать на панели дальнейшие события и историю карты (D-08). Доступ к манифесту собственного отправления остаётся (P-08).
- Входящие/исходящие отправления — представления единого раздела (решение UX-04).
- Филиал может списывать пустую коробку в собственной области; не выводить это как глобальный показатель (P-05).

## 5. Дашборд central_office — центральный офис

### Цель

Помочь ЦО обрабатывать заявки на карты из архива, принимать отправления архива, готовить коробки и направлять коробки в архив, учитывать внешнее хранение.

### Приоритетные блоки

| Приоритет | Блок | Содержание | Переход |
|---|---|---|---|
| 1 | Заявки в архив | Количество заявок ЦО, требующих ожидания/контроля; отдельный счётчик заявок с окончательным результатом «не найдена» | «Заявки в архив» с соответствующими фильтрами статусов |
| 2 | Входящие отправления | Выданные архивом карты P-09, фактическое получение которых ЦО ещё не подтвердило | «Отправления» / карточка P-09 → подтверждение фактического получения карт |
| 3 | Карты ЦО | Количество карт на балансе ЦО с отдельным обозначением карт во внешнем хранении | «Карты ЦО» |
| 4 | Быстрые действия | «Создать заявку в архив», «Упаковать коробку», «Создать отправление», «Внешнее хранение» | Разрешённые формы/разделы ЦО |
| 5 | Исходящие отправления | Отправления ЦО → архив, ожидающие завершения приёмки | «Отправления» → «Исходящие» |
| 6 | Внешнее хранение | Количество карт, которые сейчас числятся во внешнем хранении; без срока/просрочки | «Внешнее хранение» |

### Ограничения

- Заявки на архивные карты создаёт ЦО; исполнение — ответственность архива.
- Сохранение заявки не означает получение карты. Автоматическое снятие с полки/из коробки не должно отображаться как приёмка или передача (D-11/P-06).
- Внешнее хранение — состояние карт на балансе ЦО, не отправление (D-05/D-18).
- Не вводить SLA, ожидаемые даты возврата и просрочки: эти поля не утверждены (D-05).
- Списание карты — отдельное действие ЦО в соответствующем объектном контексте; не смешивать его с количеством заявок или обычной отправкой (P-04).

## 6. Дашборд archive — архив

### Цель

Помочь архиву принимать коробки от филиалов/ЦО, размещать и учитывать карты/коробки, обрабатывать заявки ЦО и отправлять запрошенные карты в ЦО.

### Приоритетные блоки

| Приоритет | Блок | Содержание | Переход |
|---|---|---|---|
| 1 | Заявки ЦО в работе | Количество отправленных заявок P-09 в состояниях `submitted` и `processing`, которые ещё не завершены и не отменены | «Заявки ЦО» с фильтром «Требуют действия» |
| 2 | Входящие отправления | Коробки филиал → архив и ЦО → архив, ещё не принятые архивом поштучно | «Отправления» → «Входящие» / приёмка коробок |
| 3 | Карты без размещения | Общее количество карт в учётной области архива без активного физического размещения на полке; внутри блока отдельно выделить карты, автоматически извлечённые из коробок/снятые с полок при сохранении заявок ЦО и ещё не переданные в отправление | «Хранение» с фильтрами «Не размещены» и «Извлечены по заявкам ЦО» |
| 4 | Быстрые действия | «Открыть заявки ЦО», «Принять отправление», «Найти карту», «Открыть хранение» | Разрешённые разделы архива |
| 5 | Отправления архив → ЦО | Отправления, созданные архивом по заявкам ЦО и ожидающие завершения приёмки | «Отправления» → «Исходящие» |
| 6 | Хранение | Количество карт/коробок в архивной учётной области; при наличии надёжных данных отдельно — число размещённых на полках | «Хранение» |

**Граница рабочей очереди P-09 и счётчика новых заявок:** рабочая очередь архива включает все отправленные заявки в состояниях `submitted` и `processing`. Заявка остаётся в ней на всём протяжении обработки, в том числе при частичной выдаче и пока хотя бы одна позиция не получила окончательный исход (receipt ЦО, not_found или отмена невыданного остатка). Отдельная очередь исходящих отправлений показывает физическую перевозку и не заменяет очередь P-09. Общий счётчик новых заявок на навигации архива считает только `submitted` — заявки, ожидающие начала обработки; переход в `processing` уменьшает этот счётчик, но не удаляет заявку из рабочей очереди. `completed` и `cancelled` исключаются из рабочей очереди и доступны в историческом представлении. `not_found` — результат отдельной позиции P-09, а не отдельный статус родительской заявки; он доступен в деталях/результатах обработки. Отдельный счётчик таких результатов на панели архива не вводится.

### Ограничения

- Обычное архивное хранение организовано только через коробки: каждая хранящаяся в архиве карта состоит в активном цикле одной коробки. На полке размещается коробка, а не карта; самостоятельное физическое размещение карты на полке запрещено.
- Исключение — временное операционное состояние по D-11/P-06: при сохранении заявки ЦО карта автоматически извлекается из коробки, остаётся в учётной области и ответственности архива, но уже не считается размещённой на хранении. До фактической передачи в отправление её нужно учитывать отдельным списком «Извлечены по заявкам ЦО»; это не отдельное хранение карты на полке.
- «В архиве» не означает «коробка на полке». Для физического размещения учитывать только размещения коробок.
- Не показывать процент заполнения, остаточную ёмкость и «свободные места» без инвентаризированной физической ёмкости (D-12).
- Архив исполняет инициированное ЦО списание карты; основания/проверки не определены, поэтому не проектировать автоматическую KPI-очередь списаний без уточнения регламента (D-13/P-04).
- Перегруппировка коробок — вспомогательная операция, не должна занимать приоритетное место на главной странице (P-03).

## 7. Дашборд admin — администратор

### Цель

Дать администратору глобальную административную картину и быстрый доступ к управлению учётными записями, организационными справочниками, структурой архива и административным аудитом.

### Приоритетные блоки

| Приоритет | Блок | Содержание | Переход |
|---|---|---|---|
| 1 | Состояние учётных записей | Количество активных/деактивированных пользователей; при необходимости распределение по четырём целевым ролям | «Пользователи» |
| 2 | Справочники | Краткие состояния филиалов, курьеров и мест хранения: активные/неактивные, если подсчёты корректны | Соответствующий справочник |
| 3 | Административный аудит | Последние административные события или количество за выбранный период; только события admin/security | «Административный аудит» |
| 4 | Быстрые действия | «Создать пользователя», «Управлять филиалами», «Курьеры», «Структура архива» | Административные разделы |
| 5 | Глобальный поиск | Переход к глобальному поиску карт, коробок и отправлений | «Глобальный поиск» |
| 6 | Требует настройки | Только проверяемые конфигурационные проблемы (например, отсутствие активных полок), если система может достоверно их определить | «Структура архива» или нужный справочник |

### Ограничения

- Admin сохраняет глобальный доступ к данным по D-07, но дашборд не превращается в операционный рабочий стол.
- Для административной стартовой страницы достаточно счётчиков пользователей и справочников и последних событий административного/безопасностного аудита. Отдельный блок системных настроек/диагностики не требуется.
- Не показывать глобальную ленту движений карт/коробок/отправлений. Операционная история остаётся в карточках объектов; admin audit — отдельная поверхность (D-16).
- Не предлагать admin выполнять обычную передачу, приёмку, размещение или исполнение заявки.
- Отдельные корректировки по P-07 не должны превращаться в быстрые кнопки на главной странице без утверждённого перечня действий и формы обоснования.
- Списание пустой коробки разрешено admin по P-05, но это контекстное действие карточки коробки, а не приоритетный виджет.

## 8. Общие правила количественных показателей

До реализации для каждого числа требуется спецификация:

| Поле | Требование |
|---|---|
| Название | Однозначное название сущности/состояния |
| Формула | Что считается одной единицей; исключение архивных/закрытых/исторических циклов |
| Scope | Текущая локация, участник отправления или глобально для admin |
| Статусы | Точные статусы, включённые в подсчёт |
| Время | Момент актуальности; не обещать real-time без соответствующего механизма |
| Переход | Фильтрованный список/очередь, из которой получено число |
| Пустое состояние | Значение 0 отличается от отсутствующего/неизвестного результата |
| Источник | Модель/запрос/сервис и тест, подтверждающий scope |

### 8.1 Согласованный состав показателей и их бизнес-семантика

Владелец продукта подтвердил, что количественные блоки являются элементами навигации: **каждый счётчик кликабелен и открывает соответствующий отфильтрованный список**. Число и список должны использовать одну и ту же выборку и один и тот же ролевой scope.

| Роль | Показатель | Согласованная семантика | Целевой переход |
|---|---|---|---|
| branch | Карты филиала | Карты, находящиеся в коробках, которые в данный момент находятся в работе в текущем филиале. Карты в отправленных коробках исключаются; при отправке коробки число уменьшается | Реестр карт, ограниченный текущим филиалом и активными коробками филиала |
| central_office | Заявки «не найдена» | Заявки ЦО с окончательным результатом «не найдена»; результат не переоткрывается, новая потребность оформляется новой заявкой (D-04) | Реестр заявок с фильтром окончательного результата «не найдена» |
| archive | Карты, извлечённые по заявкам ЦО | Карты, автоматически извлечённые из коробок/снятые с полок при сохранении заявки и ещё не переданные в отправление; ответственность остаётся у архива (D-11/P-06) | Реестр хранения/карт с фильтром «Извлечены по заявкам ЦО, не переданы» |
| admin | Пользователи, справочники, последние события admin-аудита | Достаточный административный обзор; отдельный блок системных настроек/диагностики не нужен | Соответствующие административные реестры и журнал административного/безопасностного аудита |

Остальные показатели (входящие/исходящие отправления, коробки в работе, карты ЦО во внешнем хранении, количество карт/коробок в архивной области) сохраняются в целевых ролевых блоках при условии точного определения статусов и области подсчёта.

Для branch показатель «Карты филиала» **не является общим количеством всех карт, когда-либо зарегистрированных филиалом** и не включает карты в пути или уже переданные другому подразделению. Единица подсчёта — медицинская карта, а не коробка.

Для archive показатель извлечённых карт — подмножество карт без активного размещения, а не дополнительная категория, которую следует прибавлять к общему числу карт без размещения. Карта исключается из этого счётчика после фактической передачи в отправление; до этого она остаётся в зоне ответственности архива.

Точные технические статусы, источники данных и серверные фильтры будут определены после инвентаризации моделей и запросов; названия статусов не выдумываются на этапе UX.

### 8.2 Сверка бизнес-семантики с текущей PostgreSQL-моделью

Проведена первичная инвентаризация `models.py`, `postgresql_dashboard.py`, `postgresql_shipment_workflow.py`, `postgresql_archive_workflow.py` и текущего `dashboard.html`. Ниже зафиксированы фактические поля и статусы прототипа, а не утверждение о готовности текущего интерфейса.

**Карты филиала.** В модели карта имеет взаимоисключающие `current_location_id` и `current_shipment_id`. Состав коробки задаётся активным `BoxCardMembership` (`removed_at IS NULL`) внутри открытого `BoxCycle` (`ended_at IS NULL`); сама коробка должна быть активной и иметь `current_location_id` филиала, `current_shipment_id IS NULL`. При `hand_over()` коробка и карты её активного цикла переводятся на `current_shipment_id`, а `current_location_id` очищается. Следовательно, согласованная выборка «Карты филиала» должна считать карты через активное членство в коробках, находящихся в филиале, и не включать карты после фактической передачи коробки. Черновик отправления сам по себе не должен уменьшать показатель.

**Заявки «не найдена».** В модели `ArchiveRequest` есть статусы `new`, `in_progress`, `completed`, `not_found`, `cancelled`. Окончательный исход «не найдена» хранится как `not_found`; обработчик `mark_not_found()` устанавливает этот статус и `completed_at`. Счётчик ЦО должен фильтровать `status = 'not_found'` и ограничивать заявки, созданные пользователями роли `central_office` (`requested_by`), а не считать все заявки глобально.

**Карты, извлечённые по заявкам ЦО.** Текущая модель содержит `CardPlacement` с активностью по `removed_at IS NULL` и членство в коробке через `BoxCardMembership`/`BoxCycle`. В целевом процессе D-11 заявка должна атомарно закрывать активное размещение и членство в коробке. Однако текущий `PostgreSQLArchiveWorkflow.create_requests()` не выполняет такое извлечение: активное размещение приводит к отказу «Сначала снимите карту с архивной полки», а автоматического закрытия членства/размещения в этом методе нет. При этом активное членство в коробке явно не закрывается. Это реализационное расхождение с D-11/P-06.

Целевая выборка отдельного счётчика архива после исправления D-11 должна включать карты в архивной локации (`current_location_id = archive`, `current_shipment_id IS NULL`) с активной заявкой ЦО в статусе `new`, без активного размещения и без активного членства в открытом цикле коробки. После фактической передачи карты в отправление она исключается из этого счётчика: заявка переходит в `in_progress`, карта получает `current_shipment_id`. Это подмножество карт без размещения, а не отдельное слагаемое к общему количеству.

**Существующая панель.** Текущий `postgresql_dashboard.py` считает `total_cards` как сумму карт в локации и карт в отправлениях `in_transit`, а `total_boxes` аналогично суммирует коробки в локации и в пути. `cards_in_branch` сейчас считает все карты с текущей локацией филиала, а не карты в коробках в работе. `open_requests` использует `new`/`in_progress`, но не выводит отдельный `not_found`. В `dashboard.html` показатели — обычные карточки без ссылок; присутствуют «Последние движения» и переход на `/history`. Это подтверждает, что существующая панель не реализует согласованную целевую семантику и не может служить готовым источником формул.

**Вывод для проектирования:** точные выборки и ссылки должны быть заданы отдельно для целевой панели; нельзя переиспользовать текущие переменные `total_cards`, `cards_in_branch`, `open_requests` без пересмотра. Реализация D-11 и целевые кликабельные реестры остаются задачами последующих этапов, исходники в рамках UX-05 не меняются.


### 8.4 Формулы очередей отправлений и коробок

Формулы ниже задают смысл целевых счётчиков в текущем scope UX-06: филиал → архив, ЦО → архив и архив → ЦО. Маршруты филиал → ЦО и ЦО → филиал отложены и не должны появляться в дашбордах, очередях, фильтрах или быстрых действиях текущей версии. Используется текущая логистическая локация пользователя, а не филиал происхождения карты и не автор отправления.

| Роль | Показатель | Целевая выборка | Исключения и переход |
|---|---|---|---|
| branch | Исходящие отправления в пути | Shipment.from_location_id = branch_location_id AND Shipment.to_location_id = archive_location_id AND status = 'in_transit' | Единственный исходящий маршрут филиала в текущем scope — филиал → архив. Черновики не считаются переданными курьеру; принятые и отменённые исключаются. Переход «Исходящие» + «В пути» |
| central_office | Входящие отправления | Shipment.from_location_id = archive_location_id AND Shipment.to_location_id = central_location_id AND status = 'in_transit' | Единственный входящий маршрут ЦО в текущем scope — архив → ЦО. Считать отправления, не карты и не строки манифеста. Переход «Входящие» + «В пути» |
| central_office | Исходящие отправления в пути | Shipment.from_location_id = central_location_id AND Shipment.to_location_id = archive_location_id AND status = 'in_transit' | Единственный исходящий маршрут ЦО в текущем scope — ЦО → архив. Черновики, принятые и отменённые не входят. Переход «Исходящие» + «В пути» |
| archive | Входящие отправления | Shipment.to_location_id = archive_location_id AND status = 'in_transit' AND (Shipment.from_location_id IN branch_location_ids OR Shipment.from_location_id = central_location_id) | Входящие маршруты только филиал → архив и ЦО → архив. Переход «Входящие» + «В пути» |
| archive | Исходящие отправления в пути | Shipment.from_location_id = archive_location_id AND Shipment.to_location_id = central_location_id AND status = 'in_transit' | Единственный исходящий маршрут архива в текущем scope — архив → ЦО. По D-01 он содержит отдельные карты, не коробки. Переход «Исходящие» + «В пути» |

Общие правила:
- Считается одна запись Shipment = одно отправление. Количество коробок и карт в манифесте показывается в строке/карточке отправления, но не увеличивает счётчик отправлений.
- Граница перехода в «В пути» — фактическая передача курьеру (handed_over_at заполнено и status = 'in_transit'). Черновик (status = 'draft') не считается отправленным.
- received и cancelled не входят в активные очереди. Текущий технический статус exception не следует автоматически включать в обычную очередь «В пути»: он связан с legacy-процессом инцидентов, исключённым D-03. До отдельного технического решения по удалению/миграции legacy-механизма такие записи должны быть видны в реестре как требующие отдельной обработки, но не переименовываться в новую бизнес-сущность и не прибавляться к обычному счётчику.
- Входящая очередь и счётчик приёмки используют одну выборку. Полная приёмка переводит отправление в received, после чего оно исчезает из очереди.
- Видимость завершённых отправлений определяется D-09/P-08 и UX-03: отправитель и получатель сохраняют просмотр своего отправления и манифеста, но завершённая запись не считается активной очередью.
- Фильтр направления должен быть серверным и не расширять область просмотра на чужие отправления. Текущий /shipments ограничивает список отправлениями, где локация является отправителем или получателем, но пока имеет только фильтр статуса; целевые фильтры направления должны дополнять, а не ослаблять это ограничение.

**Коробки в работе (branch / central_office).** Единица — физическая коробка (Box), не цикл (BoxCycle) и не карта. Базовая выборка: Box.status = 'active' AND current_location_id = user_location_id AND current_shipment_id IS NULL, исключая коробки с активным размещением на полке и коробки, включённые в активный манифест чернового/переданного отправления. Коробка, включённая в черновик отправления, показывается в контексте этого черновика, а не второй раз в очереди упаковки. После фактической передачи она исключается из коробок в работе и учитывается в исходящих отправлениях в пути. Карты в ней считаются отдельно по согласованному показателю «Карты филиала» только до передачи коробки.

**Коробки и размещения архива.**
- «Коробки без размещения» — активные коробки с current_location_id = archive_location_id, без current_shipment_id, без активного BoxPlacement и без активного манифеста отправления. Это очередь размещения/дальнейшей обработки, а не показатель свободной ёмкости.
- «Коробки на полках» — активные записи BoxPlacement (removed_at IS NULL) для коробок архивной локации. Единица — коробка/активное размещение, не количество циклов и не вместимость.
- Целевого показателя «Карты на полках» нет: отдельные карты на полках не размещаются. Физическое размещение карты определяется через коробку, в активном цикле которой она состоит, и активное размещение этой коробки.
- «Карты в архиве» — активные карты (Card.status = 'active') с current_location_id = archive_location_id и current_shipment_id IS NULL, состоящие в активном членстве BoxCardMembership открытого BoxCycle. Временное исключение — карты, автоматически извлечённые по активным заявкам ЦО и ожидающие передачи.
- Для обычного хранения учётное количество карт и физическое размещение коробок показываются отдельно. Количество карт внутри размещённых коробок может быть детализацией, но не самостоятельным размещением карт.
- Для каждой выборки переход ведёт в раздел «Хранение» с тем же фильтром; ноль размещений не означает, что архив пуст или имеет свободную ёмкость.

### 8.5 Внешнее хранение ЦО и административные показатели

**Внешнее хранение ЦО.** Считать медицинские карты, а не события передачи: Card.status = 'active' AND current_location_id = central_location_id AND current_shipment_id IS NULL AND custody_status IN ('at_court', 'at_insurance', 'at_external_organization'). Карта остаётся на учётном балансе ЦО; external_organization, external_since и тип внешнего хранения — атрибуты/детализация, а не отдельные единицы счёта. Возврат в ЦО сбрасывает custody_status в available и исключает карту из счётчика. Переход — «Внешнее хранение» с тем же фильтром. Не добавлять плановые даты возврата, SLA или просрочку (D-05).

**Admin — показатели справочников и пользователей.**
- Пользователи: количество активных учётных записей (User.is_active = true) в системе с разбивкой по целевым ролям branch, central_office, archive, admin. Если в базе ещё есть активные legacy viewer, их не скрывать: показывать отдельной строкой «Требуют миграции» до выполнения D-06. Неактивные записи доступны отдельным фильтром в реестре и не удаляются из истории (D-15). viewer не становится целевой ролью.
- Филиалы: количество активных записей Branch.is_active = true; неактивные филиалы доступны в реестре отдельно.
- Курьеры: количество активных записей Courier.is_active = true; неактивные курьеры доступны в реестре отдельно и не предлагаются для новых отправлений.
- Полки: количество активных записей ArchiveShelf.is_active = true. Это число заведённых мест, а не физическая вместимость и не число свободных мест. Секции — группирующий атрибут; не считать секцию отдельной полкой.
- Каждый показатель открывает соответствующий административный реестр с тем же фильтром. Для справочников не показывать проценты заполнения и остаток ёмкости.

**Последние события admin-аудита.** На главной показывать ограниченный список последних административных событий (предлагаемый объём — 5 записей) из DomainEvent с event_type LIKE 'admin.%', сортировка по occurred_at DESC, id DESC. Ссылка ведёт в /admin/audit, где уже применяется фильтр admin.%. Не включать события движения карт, коробок, отправлений, приёмки, заявок и хранения. Содержимое payload проверяется на отсутствие лишних персональных данных; подробная запись доступна только admin по D-07/D-16.


### 8.8 Запрещённые или неподтверждённые показатели

- процент заполнения архива, свободная ёмкость, остаток мест — нет достоверной физической вместимости (D-12);
- просроченные заявки/возвраты, SLA, среднее время обработки — не утверждены;
- число «потерянных» карт или инцидентов — отдельная сущность/процесс инцидентов исключён (D-03);
- число отправлений без чёткого определения статусов и направления;
- глобальное количество операций как замена административному аудиту;
- количество карт «на полках», вычисленное по учётной локации без проверки активного размещения.


### 8.9 Перекрёстная проверка быстрых действий и полномочий

Сверены быстрые действия стартовых страниц с UX-03, UX-04 и решениями D-01…D-18/P-01…P-08. Быстрое действие на дашборде — это короткий переход к разрешённой форме или очереди; оно не создаёт отдельного полномочия и не заменяет серверную проверку роли, области, объекта и состояния.

| Роль | Быстрые действия стартовой страницы | Дополнительные контекстные действия | Что запрещено/не выносится на стартовую страницу |
|---|---|---|---|
| branch | Создать карту вручную; зарегистрировать карту по существующему QR; открыть упаковку/создание коробки; создать отправление | Списать пустую коробку в собственной области (P-05) | Создание карты по ролям ЦО/архива; отправка отдельных карт; заявки ЦО; глобальный поиск; списание медицинской карты |
| central_office | Создать заявку в архив; открыть создание/упаковку коробки; создать отправление; открыть внешнее хранение | Инициировать списание медицинской карты из карточки карты/раздела карт ЦО (P-04); списать пустую коробку в собственной области (P-05) | Исполнение списания карты; регистрация карты вручную/по QR; архивное размещение; передача карты во внешнее хранение как отдельный маршрут отправления |
| archive | Открыть очередь заявок ЦО; открыть входящую приёмку; найти карту в области архива; открыть раздел хранения | Исполнить инициированное ЦО списание карты после определения оснований и проверок (P-04/D-13); списать пустую коробку в собственной области (P-05); выполнить вспомогательную перегруппировку карт по P-03 в допустимом контексте | Инициировать списание карты; создавать/регистрировать карты; выполнять отправления от имени ЦО/филиала; превращать перегруппировку в основной сценарий панели |
| admin | Управление пользователями; управление справочниками (филиалы, курьеры, структура архива); открыть административный аудит; глобальный поиск | Списать пустую коробку по узкому исключению P-05 при соблюдении условий пустоты и отсутствия активного отправления/размещения | Обычная упаковка, создание/передача/приёмка отправлений, размещение, исполнение заявок и внешнее хранение; корректировки P-07 не выводить как быстрые действия до определения перечня, формы обоснования и аудита |

**Правила применения:**

- Контекстные действия списания пустой коробки доступны всем четырём целевым ролям только в пределах их области. Это не означает, что admin получает операционный раздел коробок: для него допустимо только узкое действие над конкретной пустой коробкой по P-05. Коробка с картами, активным отправлением или действующим размещением не списывается.
- Списание медицинской карты — двухсторонний процесс: ЦО инициирует, архив исполняет. Не показывать admin или branch кнопку списания карты. Основания, обязательные документы и проверки остаются открытым предметом D-13/P-04; UX-05 не придумывает регламент.
- P-07 не превращается в универсальную кнопку «Исправить данные». До определения разрешённых типов корректировок, обязательного обоснования, ограничений неизменяемости истории и записи в admin-аудит такое действие не предлагается на стартовой странице.
- Перегруппировка коробок по P-03 — вспомогательная операция архива, не отдельная главная кнопка дашборда. Доступна только при отсутствии активного отправления/размещения; новый цикл не перезаписывает историю прежнего (D-10).
- Для branch быстрые действия создания карты и QR-регистрации остаются только в его области (P-01/P-02). Для central_office и archive эти действия не отображаются и серверно запрещены.
- «Внешнее хранение» доступно ЦО как отдельное состояние карты; оно не оформляется как отправление или дополнительный маршрут (D-05/D-18).
- «Принять отправление» для archive означает переход к входящей очереди и полную приёмку отправления, адресованного архиву; admin не получает это действие по своему глобальному просмотру.
- Недавние объекты, если блок будет включён, — это ссылки на карточки объектов в разрешённой области. Они не должны становиться глобальной лентой движений. Для branch ограничение D-08 сохраняется, а просмотр собственного завершённого отправления/манифеста — по P-08.

### 8.10 Проверка кликабельности и эквивалентности счётчиков

Для всех количественных блоков применяется единое требование: серверный запрос счётчика и серверная выборка реестра используют один и тот же предикат и один и тот же ролевой scope. Переход открывает нужный раздел UX-04 с установленными направлением, статусом, локацией и другими условиями. Пагинация влияет только на отображаемую страницу, но не на общее число совпадений.

Перекрёстная проверка целевых переходов:

- **branch:** входящие/исходящие отправления ведут в соответствующие вкладки единого раздела «Отправления»; «Коробки в работе» — в упаковку без коробок в активном размещении или манифесте; «Карты филиала» — в карты, состоящие в открытом цикле активной коробки текущего филиала, не переданной в отправление.
- **central_office:** заявки и «не найдена» ведут в собственные заявки ЦО с соответствующим статусом; входящие/исходящие отправления — в одноимённые представления; карты ЦО — в область ЦО; внешний учёт — в подвыборку карт с custody_status, отличным от available.
- **archive:** заявки ЦО ведут в рабочую очередь P-09 с фильтром родительских статусов `submitted` и `processing`; общий навигационный счётчик новых заявок считает только `submitted`. Заявка в `processing` остаётся в рабочей очереди до `completed`/`cancelled`, даже если fulfillment-отправление уже создано; само отправление отдельно отражается в исходящих отправлениях. Отменённые и завершённые P-09 доступны в историческом представлении; входящие/исходящие отправления — в соответствующие представления; коробки без размещения и коробки на полках — в разные фильтры хранения; карты фильтруются по состоянию содержащей их коробки; извлечённые по заявкам карты — в отдельную выборку ещё не переданных в отправление.
- **admin:** счётчики активных пользователей по целевым ролям, legacy viewer «требуют миграции», филиалов, курьеров и полок ведут в те же фильтры соответствующих реестров; последние admin-события ведут в /admin/audit с ограничением event_type LIKE 'admin.%'. Глобальный поиск остаётся отдельным быстрым действием, а не количественным KPI.

**Статус переходов:** в текущем прототипе не все эти фильтры реализованы. В частности, остаются необходимыми серверный фильтр направления и полноценная пагинация / полная выборка для /shipments; фильтры хранения для точных подмножеств карт и коробок; фильтр внешнего хранения; фильтры активности/ролей в admin-реестрах. Поэтому спецификация фиксирует требуемое целевое поведение, а не объявляет существующие ссылки уже эквивалентными счётчикам.


## 9. Состояния блоков и поведение

| Состояние | Поведение |
|---|---|
| Есть действия | Показывать число, короткое пояснение и прямой переход к соответствующей очереди |
| Очередь пуста | Нейтральное сообщение «Нет отправлений, ожидающих приёмки» и ссылка на общий раздел, если она полезна |
| Нет данных | Отличать от нуля; сообщить, что показатель недоступен/не рассчитан, не подменять нулём |
| Нет настроенной рабочей локации | Показать объяснение и безопасный путь обратиться к admin; не раскрывать чужие данные |
| Ошибка загрузки одного блока | Остальные блоки остаются доступными; ошибка локализована и не подменяется пустым значением |
| Недостаточно прав | Блок и ссылка не отображаются; прямой URL всё равно защищён сервером |
| Объект стал недоступен между загрузкой и переходом | Корректное сообщение без раскрытия существования чужого объекта |

Счётчики очередей не должны создавать ложную срочность цветом/бейджем, если бизнес-правило срочности не утверждено.

## 10. Согласование владельца продукта (2026-11-18)

Все пять открытых вопросов раздела согласованы:

1. **Branch — подтверждено:** показывать блок «Карты филиала». Он считает карты, находящиеся в коробках, которые сейчас в работе в данном филиале. После отправки коробки карты исключаются из количества филиала.
2. **Central office — подтверждено:** показывать отдельный счётчик заявок с окончательным результатом «не найдена».

## 2026-11-22 — superseding dashboard and queue semantics for partial P-09 and box receipt

This addendum supersedes earlier UX-05 statements that P-09 remains open only until full receipt of one fulfillment shipment, or that ordinary incoming box shipments are received as one indivisible unit.

### Archive P-09 queue

- The archive work queue includes parent requests in submitted and processing states while any actionable or nonterminal item remains.
- A request remains in processing when some cards are already issued but their actual receipt by CO is not yet confirmed, when some cards remain pending issue, or when other items are still being processed.
- The request leaves the work queue only when all items have terminal outcomes (received by CO, not_found, or cancelled as part of the unissued remainder) and the parent request is completed/cancelled according to the state machine.
- The general new-request counter continues to count only submitted requests. Opening a request does not decrement it; transition to processing does.
- The archive queue row shows request number, creation date, CO initiator, card count and parent status; patient names/card numbers remain excluded from queue rows.
- The physical outgoing transport/dispatch view is separate from the parent P-09 work queue and must not imply custody has transferred to CO before actual item receipt.

### CO P-09 view

CO can see its submitted requests and the item-level results. The request remains visible while some items are pending, issued but not yet received, or otherwise nonterminal. Item-level actual receipt confirmation is available only for cards that have physically arrived. Bulk confirmation is one atomic action over the selected arrived cards; per-card actor/time remains available in the item timeline.

### Ordinary incoming box shipments

Incoming branch → archive and central_office → archive shipments are received one box at a time. The archive incoming queue remains open until all manifest boxes and discrepancies are resolved. A received box may appear in the ready-to-place work surface immediately, without waiting for the whole shipment. Receipt counts are total manifest boxes, individually received boxes, and boxes awaiting receipt; placement is a separate state and does not change the receipt count. No card-count/seal/package check is part of receipt.

Do not merge box-level receipt counters with P-09 card-level issue/receipt counters.
