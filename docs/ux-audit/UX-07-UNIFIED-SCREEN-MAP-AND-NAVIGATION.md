# UX-07 — единая карта экранов и навигационный контракт МедАрхива

**Дата:** 2026-11-22. **Статус:** проектная screen map после предварительного согласования WF-01…WF-07. Это информационная архитектура и композиционный контракт, а не готовые графические макеты, маршруты frontend или код.

## 1. Принципы объединения

- Ровно четыре пространства: **Филиал**, **ЦО**, **Архив**, **Администрирование**. Курьер — запись справочника, не пользовательская роль.
- Первичный пункт меню — **рабочая задача**, а не отдельный статус объекта. Список, карточка и контекстная операция связаны, но не дублируются в основном меню.
- Карта, коробка, отправление, заявка — **единые шаблоны карточек** с различными действиями по роли/scope. В карточке показывать только реально разрешённые ссылки и данные; прямой URL проходит ту же серверную проверку.
- Счётчики главной страницы открывают **тот же реестр с теми же фильтрами и scope**, из которого рассчитаны; нулевое значение не означает ошибку источника.
- Обычное отправление содержит коробки; P-09 fulfillment содержит карты. Смешивать их в одной таблице без явного типа манифеста нельзя.
- Ручной поиск медицинских карт — только по ФИО, включая неполное. Сканирование QR/штрихкода — отдельный способ идентификации; номер карты/телефон могут отображаться по разрешению, но не служат полями ручного поиска.
- Никакого автоматического расширения полномочий через участие в отправлении/заявке, просмотр манифеста, таблицу хранения или аналитический вид.

## 2. Карта основных разделов по ролям

| Роль | Основное меню | Рабочие экраны | Контекстные операции (не отдельные пункты меню) |
|---|---|---|---|
| Филиал | Главная; Карты; Коробки; Отправления | WF-B01…B05 | Регистрация QR/вручную; добавить карту; создать/передать отправление; просмотр истории |
| ЦО | Главная; Карты; Коробки; Отправления; Заявки в архив; Внешнее хранение | WF-C01…C09, WF-X01 | P-09 draft/submit; получение карт; упаковка/передача коробок; инициирование списания; внешнее хранение |
| Архив | Главная; Приёмка; Хранение; Заявки ЦО; Отправления; Запросы списания | WF-A01…A10, WF-M02…M04, WF-X02…X04/X06/X07 | Получить коробку; разместить/переместить; перегруппировать **карты**; обработать P-09; списать карту по запросу; исправить ошибочную приёмку |
| Admin | Главная; Пользователи; Организация; Курьеры; Архивные полки; Глобальный просмотр; Аудит | WF-D01…D08, WF-X05 | Назначить/отозвать права; активировать/деактивировать; узкие P-07; списание пустой коробки по P-05 |

Меню «Отправления» для архива охватывает участие как отправителя P-09 fulfillment и получателя обычных коробочных отправлений; **«Приёмка» — рабочий фильтр входящих**, а не вторая независимая база. «Хранение» объединяет реестр, визуальную схему и действия с размещёнными коробками; отдельного основного пункта «Перегруппировка» нет.

## 3. Главные навигационные маршруты

### Филиал

```text
Главная (B01)
  ├─ Карты → [Поиск по ФИО] / [QR] / [Создать вручную] → Карточка карты
  ├─ Коробки → Список → Коробка (B02)
  │                         ├─ Найти карту по ФИО / QR → Добавить
  │                         └─ Создать карту в контексте коробки (B03) → Добавить
  └─ Отправления → Draft (B04) → Handover → Карточка/история (B05)
```

Из B03 возвращаться в ту же коробку и сохранённый контекст; не требовать второго поиска. Упаковка и регистрация карты — два равноправных порядка действий.

### Центральный офис

```text
Главная
  ├─ Заявки в архив → Список (C01) → Draft (C02) → Submitted (C03)
  │                                          → Входящее fulfillment (C04)
  ├─ Коробки → Упаковка (C05) → Отправления → Draft (C06)
  │                                          → Handover/история (C07)
  ├─ Внешнее хранение → Реестр (C08) → Карточка карты (C09)
  └─ Карты → Карточка → Запрос списания (X01)
```

Входящая P-09 приёмка C04 — **поштучное подтверждение карт или выбранного набора**, не новая отправка и не изменение состава заявки. Обычная отправка ЦО→архив — коробки без P-09.

### Архив

```text
Главная (A01)
  ├─ Приёмка → Входящие коробочные отправления (A02) → Карточка (A03)
  │                                                   → Принять коробку
  │                                                   → Хранение (A04)
  ├─ Хранение → [Таблица M03 ↔ Схема M02] → Полка (M04)
  │             └─ Коробка/история (A06)
  │                    ├─ Разместить (A05) / снять / переместить (X03)
  │                    ├─ Перегруппировать карты (X07)
  │                    └─ Списать пустую коробку (X06)
  ├─ Заявки ЦО → Очередь (A07) → Карточка/старт (A08)
  │                                  → Результаты всех позиций (A09)
  │                                  → Один fulfillment draft/handover (A10)
  ├─ Отправления → Все разрешённые карточки/истории
  └─ Запросы списания → Очередь → Обработка (X02)
```

**Критическое различие:** X03 перемещает **целые коробки** между полками, не меняя состав; X07 перекладывает **карты между коробками**, даже если обе коробки остаются на полках. При опустошении исходной коробки в X07 placement сохраняется, BoxCycle закрывается, показывается предупреждение. При P-09 extraction последней карты placement закрывается автоматически. Не объединять эти действия в одну кнопку.

### Администратор

```text
Главная (D01)
  ├─ Пользователи (D02) → Карточка/Права/Безопасность/История (D03)
  ├─ Организация (D04)
  ├─ Курьеры (D05)
  ├─ Архивные полки (D06)
  ├─ Глобальный просмотр (D07) → Объект → Узкая коррекция P-07 (X05)
  └─ Аудит (D08)
```

Глобальный просмотр — **read-only по умолчанию**, кроме явно разрешённых специализированных команд; не показывать обычные действия приёмки, упаковки, выдачи или размещения.

## 4. Повторно используемые шаблоны экранов

| Шаблон | Используется | Обязательные области | Не смешивать |
|---|---|---|---|
| S01 Рабочая главная | Все четыре роли | Приоритетные задачи, очереди, быстрые переходы, безопасные состояния | Главная не заменяет реестры |
| S02 Реестр | Карты, коробки, заявки, отправления, пользователи | Заголовок, фильтры, счётчик, строки, пагинация, пустое/ошибочное состояние | Фильтры по ФИО карты ≠ поиск по номеру |
| S03 Карточка карты | Branch/CO/archive по scope; admin read | Идентичность, текущая локация/custody, коробка/цикл, события, доступные действия | Самостоятельный доступ не наследуется из манифеста |
| S04 Карточка коробки | Branch/CO/archive по scope; admin read | Физическая тара, текущий BoxCycle, membership, placement, история | Физическая коробка ≠ логистический цикл |
| S05 Карточка обычного отправления | Участники | Маршрут, box manifest, статусы box receipt, timeline | Никакого списка карт в archive box shipment |
| S06 Карточка P-09 | ЦО/архив по фазе | Parent, items, результаты, один fulfillment, история | Нет частичной отправки или второго fulfillment |
| S07 Контекстная команда | Любая разрешённая операция | Проверки, влияние, подтверждение, ошибка конфликта, итог | Не делать «универсальный редактор» |
| S08 Схема/реестр хранения | Архив | Одни scope и фильтры, переход полка→коробка | Проценты без ёмкости запрещены |
| S09 Административный реестр/карточка | Admin | Scope, точные права, audit, подтверждение опасных действий | AdminSecurityAudit ≠ бизнес-история |

## 5. Композиция для следующего визуального low-fi прохода

### Рабочий экран с реестром

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ МедАрхив  [Текущая роль/локация]                     [Учётная запись]       │
├───────────────────┬─────────────────────────────────────────────────────────┤
│ Главная           │ Заголовок раздела                   [Основное действие] │
│ Карты/Коробки     │ Контекст / хлебные крошки                                │
│ Отправления       │ [Поиск/фильтры] [Активные фильтры]                       │
│ ... по роли       │ ┌─────────────────────────────────────────────────────┐ │
│                   │ │ Реестр / состояние / строки / пагинация            │ │
│                   │ └─────────────────────────────────────────────────────┘ │
└───────────────────┴─────────────────────────────────────────────────────────┘
```

### Карточка и операция

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ ← К списку / Хлебные крошки           Объект №…          [Статус]           │
│ [Текущая локация] [Ответственность] [Контекст объекта]                      │
├──────────────────────────────────────┬──────────────────────────────────────┤
│ Состав / позиции / сведения          │ Разрешённые действия                │
│                                      │ [Главное действие]                   │
│                                      │ [Другие действия]                    │
├──────────────────────────────────────┴──────────────────────────────────────┤
│ История объекта / только релевантные события                                │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Компактный экран

На узкой ширине боковая навигация сворачивается в явное меню; контент, действия, история и формы идут одной колонкой; главное действие не перекрывает таблицу и подтверждение. Широкие таблицы используют адаптированный список или горизонтальный скролл с видимыми ключевыми полями. Это **проектное требование для визуального review**, а не утверждение, что существующий frontend уже так работает.

## 6. Правила переходов, сохранения контекста и ошибок

1. Из реестра в карточку и обратно сохранять применённые фильтры, страницу и исходную вкладку, если объект остаётся доступен.
2. При открытии операции из коробки после успеха возвращать к коробке и обновлённому составу; при X07 показывать **обе** затронутые коробки и предупреждение об опустевшей.
3. Ссылка из P-09/отправления к карте или коробке показывается лишь при самостоятельном разрешении. Прямой URL не обходит scope; при потере доступа — безопасный отказ без утечки PII.
4. После handover манифест обычного отправления read-only; после submit состав P-09 read-only; для архива доступны только согласованные изменения результатов до fulfillment draft.
5. Счётчик и открываемая очередь используют один серверный фильтр; archive P-09 «новые» — только submitted. Partial receipt карт ЦО не создаёт вторую отправку.
6. Пустой список, отсутствие прав, ошибка загрузки и конфликт актуальности — **разные состояния**, не показывать «0» при ошибке источника.
7. При конкурирующей операции повторно загрузить состояние; не считать UI-предпросмотр гарантией commit.
8. Корректирующие команды требуют основания/аудита согласно своему типу, не универсальную кнопку «Изменить».
9. Переключение «Схема ↔ Таблица» в хранении не меняет выбранные фильтры, scope и единицы подсчёта; неизвестная вместимость не превращается в 0%.
10. Никаких обязательных повторных вопросов о принятых бизнес-правилах: если UI требует новой семантики, записать отдельно как непроверенное допущение.

## 7. Матрица точек входа в редкие действия

| Действие | Где открыть | Куда вернуться | Условие |
|---|---|---|---|
| Перегруппировать карты X07 | Хранение → коробка → состав | Обе коробки и обновлённая история | Archive, box_repack, нет конфликтов |
| Переместить коробки X03 | Хранение → выбранные коробки | Реестр/полка | Archive, box_place, одна цель, атомарно |
| Исправить приёмку X04 | Приёмка → отправление → событие | Карточка отправления и timeline | Отдельное полномочие и причина |
| Инициировать списание карты X01 | ЦО → карта | Карточка карты и запрос | ЦО в scope |
| Исполнить списание X02 | Архив → запросы списания | Запрос/история | Archive с полномочием |
| Списать пустую коробку X06 | Коробка | Карточка/реестр | Нет карт, активного цикла, shipment, placement |
| Коррекция P-07 X05 | Admin → глобальный объект | Объект/история/аудит | Только разрешённый тип |
| Получить карту P-09 C04 | ЦО → входящее fulfillment | Карточка shipment/P-09 | Только фактически полученные карты |

## 8. Открытые вопросы именно визуального UX, не бизнес-правил

- Нужен графический low-fi review 4 основных рабочих пространств, реестра, карточки коробки, P-09 и X07, включая компактную ширину, keyboard focus и состояния подтверждения/ошибки.
- Нужна проверка названий пунктов меню и иерархии вложенности на прототипе; эта screen map — **проектная структура**, не утверждённый набор URL/роутов.
- Расширенная управленческая аналитика WF-06 остаётся концепцией: нет новой роли руководителя, процентов вместимости без инвентаризации и неутверждённого экспорта.
- Технические DB-команды и точные state machine P-04/P-07, а также конфликт раннего разрешения многоисточниковой перегруппировки и позднего запрета массового извлечения карт требуют отдельной технической сверки перед реализацией; UX не должен обходить эти ограничения.

**Итог:** все WF-01…WF-07 привязаны к единой навигационной модели, но UX-07 **ещё не закрыт**. Следующий шаг — визуальные low-fi компоновки и review; UX-08 не начат. Код, ORM, API, миграции и тесты не менялись.
