# UX-07 / WF-01 — wireframes филиала: карта → коробка → отправление

Дата: 2026-11-22. Статус: **low-fidelity wireframes v1, проектная гипотеза**. Без реализации. Исходные правила: UX-04, UX-06 и `UX-07-SCREEN-FLOWS-AND-BRANCH-SHIPMENT.md`. Схемы показывают структуру и действия, не финальные цвета/стили.

## WF-B01. Рабочая точка филиала

```text
┌──────────────────────────────────────────────────────────────────────┐
│ МедАрхив / Филиал [название]                 [Сотрудник] [Выход]      │
├─────────────────┬────────────────────────────────────────────────────┤
│ Главная         │ Работа с медицинскими картами                      │
│ Карты           │                                                    │
│ Коробки         │ [ + Создать коробку ]   [ + Зарегистрировать карту ]│
│ Отправления     │                                                    │
│                 │ Продолжить работу                                  │
│                 │ [Коробки в подготовке] [Черновики отправлений]      │
│                 │                                                    │
│                 │ Недавние исходящие отправления →                   │
└─────────────────┴────────────────────────────────────────────────────┘
```

Главная страница не копирует все старые пункты меню в карточки. Основной маршрут — создать коробку, затем наполнять её; альтернативный — зарегистрировать карты заранее. Показатели и счётчики строго по UX-05, без выдуманных KPI.

## WF-B02. Коробка — единая рабочая область наполнения

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← Коробки / Коробка № [номер]                     [Статус]           │
│ Карт: [N]                              [К отправлению] [Ещё ▾]      │
├──────────────────────────────────────────────────────────────────────┤
│ ДОБАВИТЬ КАРТУ                                                       │
│ [ Сканировать QR / штрихкод ] [ Найти карту ] [ Создать вручную ]     │
│                                                                      │
│ [Контекстная область: камера/сканер ИЛИ поиск ИЛИ создание]          │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ КАРТЫ В КОРОБКЕ                                                      │
│ [Номер карты]  [ФИО]  [Дата рождения]        [Удалить из коробки]    │
│ [Номер карты]  [ФИО]  [Дата рождения]        [Удалить из коробки]    │
│                                                                      │
│ [ + Добавить ещё ]                     [ Перейти к отправлению → ]    │
└──────────────────────────────────────────────────────────────────────┘
```

**Смысл объединения:** сканирование, поиск и создание — **три режима одной рабочей области**, а не три страницы с возвратом в коробку. При ручном поиске карты внутри коробки действует утверждённый поиск **только по ФИО** (включая неполное ФИО); сканирование QR/штрихкода — самостоятельный способ идентификации карты. Ручного поиска по номеру, телефону или дате рождения нет. Это не ограничивает обязательные номер карты/ФИО/дату рождения при создании новой карты. При создании карты контекст коробки сохраняется; успешное создание может сразу добавить карту после отдельной серверной проверки.

**Режим «карта не найдена»:** показывать «Создать карту здесь», с сохранением номера коробки. **Дубль номера:** блокировать создание, не раскрывая чужой объект. **Совпадение ФИО:** показать доступные совпадения, запросить подтверждение самостоятельной карты. **Коробка пустая:** доступно добавление, недоступно включение в отправление.

## WF-B03. Самостоятельная регистрация карты

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← Карты                         Регистрация медицинской карты        │
│ [ Сканировать QR ] [ Ввести вручную ]                                 │
├──────────────────────────────────────────────────────────────────────┤
│ Номер карты *           [________________]                            │
│ ФИО *                   [________________]                            │
│ Дата рождения *         [________________]                            │
│ Телефон                 [________________]                            │
│                                                                      │
│ [Проверка номера и возможных совпадений ФИО]                         │
│                                                                      │
│ [ Отмена ]                                   [ Создать карту ]        │
└──────────────────────────────────────────────────────────────────────┘
```

QR из внешней МИС заполняет обязательные данные и телефон при наличии. Сканирование не отменяет проверку номера. После сохранения — карточка созданной карты; дальнейшее помещение в коробку — отдельное понятное действие. При открытии из WF-B02 вместо ухода в реестр возвращаемся в ту же коробку.

## WF-B04. Отправление — подготовка и подтверждение

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← Отправления                  Новое отправление                     │
│ Маршрут: Филиал → Архив (фиксирован)                                 │
├──────────────────────────────────────────────────────────────────────┤
│ Выбрать подготовленные непустые коробки                              │
│ [✓] Коробка №...    [N карт]                                         │
│ [ ] Коробка №...    [N карт]                                         │
│                                                                      │
│ Курьер * [ Выберите активного курьера             ▾ ]                │
│                                                                      │
│ Итого: [N коробок]            [ Сохранить черновик ]                  │
├──────────────────────────────────────────────────────────────────────┤
│ ПОДТВЕРЖДЕНИЕ ФАКТИЧЕСКОЙ ПЕРЕДАЧИ (после сохранения черновика)      │
│ [Сводка всех коробок и выбранного курьера]                           │
│ [ Назад к редактированию ] [ Подтвердить передачу ]                  │
└──────────────────────────────────────────────────────────────────────┘
```

Нельзя выбрать пустую коробку, запрещённый маршрут или создать заявку филиала. Перед handover повторно проверяются состав и курьер. Курьер обязателен уже при создании черновика; незавершённый черновик обычного отправления у сотрудника может быть только один. После handover черновик и manifest не редактируются; сотрудник видит результат в карточке отправления. **Ранее назначенный курьер, деактивированный после назначения, не блокирует handover**; для нового назначения/замены доступны только активные курьеры.

## WF-B05. Карточка отправления после передачи

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← Отправления    Отправление № [номер]       [Статус]                 │
│ Отправитель: филиал   Получатель: архив    Курьер: [ФИО]             │
├──────────────────────────────────────────────────────────────────────┤
│ КОРОБКИ: №...  №...                                                  │
│                                                                      │
│ ХРОНОЛОГИЯ                                                          │
│ [Дата] Создано → [Дата] Передано → [Дата] Получение коробок архивом │
│                                                                      │
│ [Вернуться к отправлениям]                                           │
└──────────────────────────────────────────────────────────────────────┘
```

Доступ к своему shipment, manifest коробок и timeline сохраняется после передачи. Ссылки на самостоятельные карточки коробок и карт показываются **только** при отдельном текущем праве. Пациентские данные в строках реестра отправлений не показываются.

## Wireflow: два равноправных пути

```text
A: Карты → Регистрация карты (WF-B03) ─────┐
                                          ↓
                                     Коробка (WF-B02)
                                          ↑
B: Коробки → Создать коробку ──────────────┘
                                          ↓
                                Добавить существующую карту
                                  ИЛИ создать прямо в коробке
                                          ↓
                             Подготовка отправления (WF-B04)
                                          ↓
                              Подтверждение handover
                                          ↓
                             Карточка отправления (WF-B05)
```

## Матрица действий и критерии проверки

| Экран | Главное действие | Успех | Запрет/ошибка |
|---|---|---|---|
| WF-B01 | Начать коробку или регистрацию | Открыта нужная рабочая область | Не показывать чужие локации и недоступные разделы |
| WF-B02 | Найти/сканировать/создать и добавить карту | Карта в текущей коробке, счётчик обновлён | Дубль, недоступная карта, конфликт состава |
| WF-B03 | Создать карту | Уникальная карта зарегистрирована | Отсутствует обязательное поле, номер занят, совпадения требуют проверки |
| WF-B04 | Сохранить черновик, затем подтвердить передачу | Полный manifest зафиксирован | Пустая коробка; не выбран курьер при создании; изменённый состав; новый выбор неактивного курьера (но не старое назначение) |
| WF-B05 | Смотреть manifest и timeline | Доступна история своего отправления | Ссылки не расширяют права на независимые объекты |

## Что проверять на UX-08

1. Может ли сотрудник самостоятельно выбрать «сначала карта» или «сначала коробка»?
2. Может ли создать отсутствующую карту, **не потеряв коробку и контекст**?
3. Понимает ли разницу между «сохранить черновик» и «подтвердить фактическую передачу»?
4. Понимает ли, где увидеть состояние отправления после передачи?
5. Не создаёт ли объединённая рабочая область перегрузку? При необходимости режимы скрывать до выбора действия, но не возвращать лишние переходы.

**Ограничение:** текстовые схемы являются low-fidelity wireframes; не заменяют визуальную проверку макетов на разных ширинах, интерактивный прототип UX-08 и фактическое тестирование UX-11.


## 2026-11-23 — WF-08: основной путь — непрерывное QR-сканирование

См. `UX-07-WF-08-CONTINUOUS-QR-SCANNING.md`. В рабочем режиме «Карты» и открытой коробки **не требуется нажимать кнопку «Сканировать QR» перед каждым считыванием**: HID-сканер вводит полный QR с терминатором, система определяет контекст и выполняет проверку. В «Картах» — поиск/регистрация, в «Коробке» — поиск/регистрация и добавление в закреплённую коробку. Ручной поиск по ФИО и ручное создание остаются альтернативой. Сканирование не перехватывает ввод в формах; конфликтные сканы не изменяют данные. **Автоматическое сохранение новой карты без подтверждения пока проектная рекомендация, не принятое бизнес-правило:** текущий PostgreSQL-сервис требует подтверждения, см. WF-08 §6.
