# UX-07 / WF-02 — рабочее место архива: приёмка коробок и размещение

Дата: 2026-11-22. Статус: **low-fidelity wireframes v1**, проектное предложение, не реализованный интерфейс. Принцип: workflow-first; не копировать существующие страницы без необходимости.

## Источники и неизменяемые правила

- `UX-04-information-architecture-and-navigation.md` §3.3 — разделы и права архива.
- `UX-05-dashboard-design.md` — входящие коробки, коробки без размещения, коробки на полках; не смешивать эти счётчики с количеством карт.
- `UX-06-DESIGN-EXIT-AND-UX07-HANDOFF.md` — маршруты, поштучная приёмка коробок, отдельное размещение и P-09.
- Принимаются **коробки по одной**, не отправление целиком. Не пересчитывать карты внутри коробки. Факт приёмки и размещение на полке — **две отдельные операции**. После приёмки коробка относится к ответственности архива.
- Хранение карт в архиве — внутри коробок; на полках размещаются только коробки. Временное извлечение карты при P-09 не является отдельным способом хранения.
- Входящие маршруты: филиал → архив, ЦО → архив. Заявки для входящих коробок не нужны. Архив → ЦО — отдельный процесс исполнения P-09.

## WF-A01. Рабочая точка архива

```text
┌──────────────────────────────────────────────────────────────────────┐
│ МедАрхив / Архив                                  [Профиль]         │
├────────────────┬─────────────────────────────────────────────────────┤
│ Главная        │ СЕГОДНЯ В АРХИВЕ                                    │
│ Приёмка        │ [Входящие отправления] [Коробки без размещения]     │
│ Хранение       │ [Новые заявки ЦО]      [Заявки в работе]            │
│ Заявки ЦО      │                                                     │
│ Отправления    │ [ Перейти к приёмке → ] [ Разместить коробки → ]     │
│                │                                                     │
│                │ Недавние события в пределах доступной области      │
└────────────────┴─────────────────────────────────────────────────────┘
```

Счётчик «новые заявки ЦО» — только `submitted`, рабочая очередь — `submitted` + `processing`. Эти карточки ведут в отдельный процесс P-09; **не смешивать** его с входящей коробочной приёмкой. Формулы счётчиков только по UX-05.

## WF-A02. Очередь входящих коробочных отправлений

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Приёмка / Входящие отправления                                      │
│ [Ожидают] [Частично приняты] [Завершённые]     [Поиск № отправления] │
├──────────────────────────────────────────────────────────────────────┤
│ Отправление   Откуда       Коробок принято / всего     Действие      │
│ №...          Филиал ...   2 / 5                      [Открыть →]    │
│ №...          ЦО           0 / 3                      [Открыть →]    │
└──────────────────────────────────────────────────────────────────────┘
```

В строках нет ФИО пациентов, номеров медицинских карт и содержимого коробок. Статусы и счётчики не предполагают приёмки всех коробок одной кнопкой. **В основной шапке карточки архива не показывать ФИО создателя отправления и ФИО курьера**; в истории доступны ФИО фактических исполнителей событий согласно UX-06, не курьера.

## WF-A03. Карточка отправления — поштучная приёмка коробок

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← Входящие / Отправление №...         [Статус отправления]           │
│ Маршрут: филиал/ЦО → архив       Получено: 2 из 5 коробок          │
├──────────────────────────────────────────────────────────────────────┤
│ КОРОБКИ ПО МАНИФЕСТУ                                                │
│ №001    [Принята]          [Смотреть событие]                        │
│ №002    [Принята]          [Смотреть событие]                        │
│ №003    [Ожидается]       [ Подтвердить приёмку ]                    │
│ №004    [Ожидается]       [ Подтвердить приёмку ]                    │
│ №005    [Ожидается]       [ Подтвердить приёмку ]                    │
├──────────────────────────────────────────────────────────────────────┤
│ РАСХОЖДЕНИЯ                          [ Зафиксировать расхождение ]  │
│ [Недостающая / лишняя коробка — отдельная запись]                    │
├──────────────────────────────────────────────────────────────────────┤
│ ХРОНОЛОГИЯ: создано → передано → приёмка №001 → приёмка №002 → ...   │
└──────────────────────────────────────────────────────────────────────┘
```

**Операция «Подтвердить приёмку» действует только на выбранную коробку.** Подтверждение создаёт отдельное событие и переводит её под ответственность архива; оно не размещает коробку на полке. Не требовать сверки количества карт, сканирования вложенных карт или сверки пломбы. Недостающие коробки остаются ожидаемыми в исходном манифесте; лишние отображаются отдельно, не подменяя исходный состав. Детали типа расхождения, исполнитель и время доступны в контекстной истории.

После приёмки рядом с коробкой можно предложить **«Перейти к размещению»**, но это переход в следующую операцию, не автоматическое размещение. Самостоятельный доступ к карточке коробки проверяется заново.

## WF-A04. Хранение — очередь коробок без размещения

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Хранение / [Без размещения] [На полках] [Все коробки]               │
│ [Найти коробку] [Фильтр секции]                                      │
├──────────────────────────────────────────────────────────────────────┤
│ Коробка       Текущее размещение        Действие                     │
│ №001          Нет                       [ Разместить → ]             │
│ №002          Нет                       [ Разместить → ]             │
│ №010          Секция А / Полка 3        [ Открыть → ]                │
└──────────────────────────────────────────────────────────────────────┘
```

Показывать только доступные архиву коробки; не смешивать «в архиве» с «на полке». Не показывать «карты на полках» как самостоятельную физическую единицу.

## WF-A05. Размещение коробки — отдельное действие

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← Хранение / Коробка №001                                           │
│ Состояние: принята архивом     Размещение: отсутствует               │
├──────────────────────────────────────────────────────────────────────┤
│ РАЗМЕСТИТЬ КОРОБКУ                                                   │
│ Секция       [Выбрать активную секцию ▾]                              │
│ Полка        [Выбрать активную полку ▾]                               │
│                                                                      │
│ [Отмена]                                     [ Подтвердить размещение]│
├──────────────────────────────────────────────────────────────────────┤
│ ИСТОРИЯ: приёмка → размещение (после успешного действия)             │
└──────────────────────────────────────────────────────────────────────┘
```

Список полок — только активные допустимые места. Повторно проверить доступность коробки, полки и отсутствие конфликта активного размещения. Перемещение уже размещённой коробки — отдельное действие с прежней/новой полкой и отдельным событием; **причину для обычного перемещения не требовать**. Допускается перемещение заполненной и пустой коробки без изменения состава.

## WF-A06. Контекстная карточка коробки и история

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Хранение / Коробка №...              [Активная]                      │
│ Текущая секция/полка: ...      [ Переместить ] [ Снять с полки ]     │
├──────────────────────────────────────────────────────────────────────┤
│ [Состав] [История размещений] [История логистических циклов]         │
│                                                                      │
│ Состав карт — только в рамках самостоятельных прав архива            │
│ События: дата, сотрудник, действие, прежнее/новое место              │
└──────────────────────────────────────────────────────────────────────┘
```

Коробка и её логистический цикл — разные сущности. История размещения сохраняется при перемещении. Доступ к картам не следует из одной лишь ссылки на манифест отправления.

## Wireflow

```text
Рабочая точка архива
    ├── Входящие → Отправление → Приёмка каждой коробки ─┐
    │                        └→ Расхождение / история    │
    ├── Хранение → Коробки без размещения ←───────────────┘
    │                        ↓
    │                  Выбор полки
    │                        ↓
    │                 Размещение коробки
    │                        ↓
    │                 Карточка коробки → Перемещение / история
    └── Заявки ЦО → отдельный сценарий WF-03 (P-09)
```

**UX-решение:** приёмка и размещение остаются разными бизнес-операциями, но сотрудник может перейти от результата приёмки к размещению одной понятной ссылкой. Это сокращает навигацию без смешивания ответственности и фактического размещения.

## Проверки и пограничные состояния

| Ситуация | UX-реакция |
|---|---|
| Нет входящих отправлений | Пустое состояние без неработающих кнопок |
| Получена только часть коробок | Счётчик по коробкам, остальные ожидают; не показывать полную приёмку |
| Повторная попытка принять ту же коробку | Не создавать второе событие; показать актуальное состояние |
| Недостающая коробка | Отдельное расхождение, исходная позиция остаётся ожидаемой |
| Лишняя коробка | Отдельное расхождение, не изменять манифест |
| Коробка принята, но не размещена | Видна в очереди «Без размещения» |
| Полка деактивирована / коробку переместил коллега | Отклонить устаревшее действие и предложить обновить данные |
| Нет права на связанную карту | Не раскрывать её данные через историю/манифест |
| Обычное перемещение коробки | Не запрашивать причину; записать прежнее/новое место, сотрудника и время |

## Критерии готовности WF-02 и передача дальше

- Нигде нет действия «Принять всё отправление» вместо поштучной приёмки коробок.
- Нет автоматического размещения при приёмке и самостоятельного размещения медицинской карты на полке.
- Нет сверки карт внутри коробок.
- Очередь заявок P-09 не смешана с входящими коробочными отправлениями.
- Показаны пустые, частичные, ошибочные состояния и контекстная история.
- Следующий wireframe-блок: **WF-03, ЦО ↔ архив, групповая заявка P-09**, с одним полным fulfillment shipment и item-level receipt в ЦО.

Это схематические текстовые макеты; они не заменяют визуальную проверку на устройствах, UX-08 и UX-11.


## 2026-11-22 — связь хранения с аналитической схемой и реестром (WF-06)

В дополнение к операционным WF-A04/A05/A06 раздел «Хранение» получает два **проектных режима просмотра**: визуальная схема секций/полок и табличный реестр коробок; подробности — `UX-07-WF-06-ANALYTICS-AND-STORAGE-VIEWS.md`. Эти режимы используют одну разрешённую серверную выборку и сохраняют фильтры при переключении. Они **не заменяют отдельные операции** приёмки и размещения и не открывают новые роли/права.

По D-12 пока показываются только фактические количества, не проценты заполненности и не «свободные места». Иерархия помещения/стеллажи остаётся будущей концепцией, не подтверждённой в текущей PostgreSQL-модели.


## 2026-11-22 — WF-X07: оптимизация размещения карт внутри коробок

**Не путать с перемещением физических коробок между полками.** Из раздела «Хранение» и карточки коробки архивный сотрудник должен иметь доступ к отдельному действию **«Перегруппировать карты»**: выбрать карты исходной коробки и переложить в существующую (включая уже размещённую на полке) или новую коробку. Подробный wireframe — `UX-07-WF-07-EXCEPTIONS-WRITEOFF-BULK-CORRECTIONS.md`, WF-X07. По P-03/D-11 и DB-61 предварительно снимать исходную/целевую коробку с полки не нужно; изменение membership/BoxCycle атомарно; placement сохраняется. Если исходная коробка опустела, показать предупреждение и оставить её на полке, пока пользователь не выполнит отдельный `box_unplace`. При P-09 extraction последней карты действует другое правило — placement закрывается автоматически. Это ранее согласованный рабочий процесс, а не новая функция для повторного утверждения.
