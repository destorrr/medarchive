# UX-07 / WF-04 — ЦО: отправка коробок в архив и внешнее хранение

Дата: 2026-11-22. Статус: **low-fidelity wireframes v1 — на предварительное рассмотрение**. Только проектирование, без изменений приложения.

## Основания и границы

- `UX-04-information-architecture-and-navigation.md` §§3.2, 6.4; `UX-06-SHIPMENT-ROUTE-AND-STATE-AUDIT.md` §§1–4; `UX-06-OBJECT-DETAIL-AND-TIMELINE-CONTRACT.md` §§10–14, 24–27; `PRODUCT-DECISIONS-D-01-D-18.md` (D-05).
- ЦО **отправляет в архив только коробки** с картами без предварительной заявки. Заявки P-09 относятся к обратному маршруту **архив → ЦО**, а не к этому процессу.
- Внешнее ответственное хранение — **не отправление**, не отдельный транспортный маршрут и не заявка; карта остаётся на балансе ЦО и исключается из обычной упаковки/отправки до возврата.
- Существующие страницы не обязаны сохраняться. Интерфейс строится вокруг рабочих процессов, при сохранении независимых доменных операций и ролевых ограничений.

## Целевая структура рабочего пространства ЦО

На рабочей точке ЦО показывать равноправные переходы к **Заявкам в архив** (WF-03), **Упаковке и отправке коробок** (WF-04), **Приёмке карт из архива** (WF-03) и **Внешнему хранению**. Не смешивать две противоположные перевозки в одной форме и не предлагать отправление коробок как «исполнение заявки».

## WF-C05. Коробки и упаковка ЦО

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ ЦО / Коробки и упаковка                       [+ Создать коробку]       │
│ [В подготовке] [Мои доступные коробки]  [Поиск коробки]                │
├─────────────────────────────────────────────────────────────────────────┤
│ Коробка №...       Карт: N     [Открыть и наполнить →]                  │
│ Коробка №...       Карт: M     [Открыть и наполнить →]                  │
├─────────────────────────────────────────────────────────────────────────┤
│ [Выбрать готовые коробки и оформить отправление в архив →]             │
└─────────────────────────────────────────────────────────────────────────┘
```

Цель экрана — не переписывать структуру филиала, а повторно использовать понятный UX-паттерн **«коробка как единая рабочая область»** из WF-01. Доступные операции наполнения, извлечения, создания карт и изменения состава определяются полномочиями ЦО и состоянием объектов; нельзя автоматически переносить на ЦО все права филиала. **Карты во внешнем хранении не предлагаются** к добавлению в обычную коробку. Действия над коробкой выполняются только после серверных проверок её локации, статуса и логистического цикла.

## WF-C06. Отправление ЦО → архив: выбор коробок и курьера

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ ЦО / Новое отправление                    Маршрут: ЦО → архив           │
│ Получатель: Архив (определён маршрутом)                               │
├─────────────────────────────────────────────────────────────────────────┤
│ ДОСТУПНЫЕ НЕПУСТЫЕ КОРОБКИ                                             │
│ [✓] №...    N карт                                                      │
│ [ ] №...    M карт                                                      │
│                                                                         │
│ Курьер *   [Выбрать активного курьера из общего справочника ▾]        │
│                                                                         │
│ [Отмена]                                  [Сохранить черновик →]        │
└─────────────────────────────────────────────────────────────────────────┘
```

Отправление содержит **только коробки**; карточные позиции внутрь manifest не включаются. Пустую коробку нельзя выбрать, пустое отправление запрещено. Курьер **обязателен уже при создании черновика**. У одного сотрудника ЦО одновременно может быть только **один собственный незавершённый черновик обычного отправления**. При попытке создать второй интерфейс предлагает продолжить существующий; другие сотрудники ЦО могут иметь собственные черновики.

Автор может до handover изменять набор коробок, заменить курьера активным из общего справочника, отменить черновик без причины. Если уже назначенный курьер позднее деактивирован, ранее сохранённое назначение остаётся действующим для handover; нельзя вновь выбирать деактивированного курьера. Изменения чернового manifest и промежуточные назначения курьера не создают отдельные записи бизнес-истории.

## WF-C07. Подтверждение фактической передачи и последующее отслеживание

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ Отправление №...                                    [Черновик]         │
│ ЦО → Архив     Коробок: N     Курьер: ФИО     Автор: ФИО              │
├─────────────────────────────────────────────────────────────────────────┤
│ МАНИФЕСТ КОРОБОК                                                      │
│ №...  №...  №...                                                       │
│ [Редактировать состав]   [Изменить курьера]   [Отменить черновик]      │
│                                                                         │
│ [Подтвердить фактическую передачу всех коробок →]                     │
├─────────────────────────────────────────────────────────────────────────┤
│ ПОСЛЕ ПЕРЕДАЧИ: [В пути / Принято архивом]                            │
│ Коробка №...  [Принята / Ожидается]                                    │
│ Хронология: создание → передача → приёмка отдельных коробок          │
└─────────────────────────────────────────────────────────────────────────┘
```

Только активный **автор черновика** подтверждает передачу; если он деактивирован, admin может переназначить авторство другому активному сотруднику ЦО по согласованной процедуре, но не передавать вместо него. Одно подтверждение фиксирует весь исходный manifest и курьера. После передачи набор коробок и курьер неизменяемы, редактирование закрыто. В архиве поштучно принимают коробки, а не медицинские карты; расположение на полке оформляется отдельно.

ЦО постоянно видит своё отправление, маршрут, карточку, manifest коробок и историю его событий, включая завершённые отправления, но **не получает через ссылку право на независимую карточку или последующую историю переданной коробки/карты**. В реестре ЦО не показывать курьера, ФИО пациентов и номера карт; в собственной детальной карточке отправления показывать разрешённые поля, в том числе snapshot ФИО курьера. Поля сотрудника архива на его карточке должны быть минимальны согласно UX-06 (без ФИО создателя и курьера в верхней части).

## WF-C08. Внешнее ответственное хранение — список

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ ЦО / Внешнее ответственное хранение                                    │
│ [На внешнем хранении] [История возвратов — в карточке карты]          │
│ [Найти доступную карту]                                               │
├─────────────────────────────────────────────────────────────────────────┤
│ № карты   ФИО             Тип хранения     Организация    Действие   │
│ ...       ...             ...              ...            [Открыть]  │
│                                                                         │
│ Это НЕ транспортное отправление; курьер и коробка не назначаются       │
└─────────────────────────────────────────────────────────────────────────┘
```

Отдельный раздел отвечает на вопрос «Какие карты сейчас находятся во внешней организации?», а не «Какие отправления ещё едут?». Поиск, пациентские поля и связанные карточки только в разрешённом scope ЦО. История хранения/возврата должна быть привязана к карте, а не превращаться в глобальный операционный журнал.

## WF-C09. Карточка карты → передача во внешнее хранение / возврат

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ ЦО / Карта №...               [На балансе ЦО] [Текущее состояние]      │
├─────────────────────────────────────────────────────────────────────────┤
│ ВНЕШНЕЕ ХРАНЕНИЕ                                                      │
│ Тип хранения          [Выбрать ▾]                                     │
│ Организация           [___________________________]                   │
│ Комментарий           [___________________________]                   │
│                                                                         │
│ [Отмена]                       [Отметить передачу во внешнее хранение]│
├─────────────────────────────────────────────────────────────────────────┤
│ КОГДА КАРТА УЖЕ НА ВНЕШНЕМ ХРАНЕНИИ                                    │
│ Тип / Организация / Комментарий / Дата передачи                       │
│ [Отметить фактический возврат в ЦО]                                   │
│ Даты передачи и возврата — в хронологии карты                         │
└─────────────────────────────────────────────────────────────────────────┘
```

В форме сохраняются только **тип, организация, комментарий и даты событий** по D-05. Не вводить обязательные акт, номер приказа, внешнего ответственного, план возврата, SLA и просрочку. Указывать организацию для фактической передачи; комментарий — минимальное контекстное поле, не превращать в дополнительную регистрационную форму. **Не делать новый shipment и не менять учётную локацию с ЦО на архив/третье лицо.** До возврата блокируются обычная упаковка и отправка такой карты. После возврата снова действуют общие проверки её состояния/прав для дальнейших операций; не выполнять автоматическую упаковку.

## Совместная схема переходов

```text
ЦО / Рабочая точка
 ├─ Коробки → открыть/наполнить → выбрать непустые коробки
 │                                  ↓
 │                        черновик ЦО → Архив + курьер
 │                                  ↓
 │                        один полный handover автором
 │                                  ↓
 │                        отслеживание receipt коробок архивом
 │                                  ↓
 │                        история своего отправления
 ├─ Карты ЦО → карточка карты → отметить внешнее хранение
 │                                  ↓
 │                        список на внешнем хранении
 │                                  ↓
 │                        возврат → доступные операции ЦО
 └─ Заявки в архив / Приёмка карт ← отдельный WF-03 (P-09)
```

## Проверяемые состояния и ошибки

| Ситуация | Реакция интерфейса |
|---|---|
| Сотрудник уже имеет незавершённый обычный draft | Не создавать второй; предложить открыть свой черновик |
| Нет подходящих коробок | Пустое состояние со ссылкой на упаковку; отправление не создавать |
| Пустая коробка или уже участвует в другом процессе | Исключить/отклонить на сервере, объяснить причину без раскрытия чужих данных |
| Курьер не выбран | Черновик создать нельзя |
| Курьер деактивирован после сохранённого назначения | Handover с существующим назначением допустим; замена — только на активного |
| Другой сотрудник открыл чужой draft | Только доступ в пределах авторизации; никаких кнопок изменения или handover |
| Состав коробки изменился параллельно | Запретить устаревшее подтверждение, предложить обновить manifest |
| Архив принял часть коробок | Отслеживать receipt по коробкам, без автоматического закрытия полного отправления |
| Карта находится во внешнем хранении | Не разрешать включать её в коробку/обычную отправку |
| Внешняя передача/возврат уже зафиксированы | Не дублировать событие; показать актуальное состояние карты |
| Нет доступа к карте/истории | Не раскрывать объект прямой ссылкой, через список или поиск |

## UX-проверки и статус

**Предложения UX-07, не новые бизнес-правила:** общий способ работы с коробками у филиала и ЦО (с учётом различий прав); отдельная короткая форма внешнего хранения внутри карточки карты; контекстный переход от отправления к просмотру его текущей приёмки; сохранение фильтров при возврате в реестры.

**Проверить в UX-08:** различают ли сотрудники два независимых сценария ЦО: «получить карты по заявке из архива» (WF-03) и «отправить коробки из ЦО в архив» (WF-04); понимают ли, что внешнее хранение — статус карты, а не транспортный маршрут; способны ли работать с коробкой без лишней навигации.

**Следующий блок:** WF-05 — административный интерфейс: пользователи, роли и отдельные права, филиалы, курьеры, структура хранения, аудит, допустимые корректировки.

**Ограничения:** схемы текстовые low-fidelity; не считать браузерной реализацией, UX-08-прототипом или результатом тестирования.
