# UX-07 / WF-05 — административное рабочее пространство МедАрхива

Дата: 2026-11-22. Статус: **low-fidelity wireframes v1, для предварительного рассмотрения**. Изменения только проектной документации.

## 0. Источники и обязательные границы

- `UX-04-information-architecture-and-navigation.md` §3.4 — шесть административных разделов, глобальный поиск и раздельный аудит.
- `UX-03-target-role-permission-matrix.md` §§4, 7 — глобальный read, четыре роли, исключение P-05 без права выполнять обычные операции.
- `UX-06-ADMIN-SECURITY-AUDIT-CONTRACT.md` — разделение `DomainEvent` и `AdminSecurityAudit`, минимизация событий, запрет отображения произвольного JSON.
- `UX-06-OBJECT-DETAIL-AND-TIMELINE-CONTRACT.md` — глобальный read объектов и только объектная бизнес-история.
- `PROGRESS.md`, последние принятые решения 2026-11-21/22 — пользователь, логин, роль/локация, курьеры, полки, `card_correct`, `card_number_correct`, пароль, деактивация.

**Роль admin — не пятая операционная роль.** Администратор глобально просматривает карты, коробки, заявки и отправления, но не получает кнопки обычной упаковки, приёмки, выдачи, размещения, подтверждения handover, обработки заявки P-09 или внешнего хранения. Особые разрешённые действия: списание пустой коробки по P-05, контролируемая корректировка номера карты по `card_number_correct`, отдельные административные корректировки по P-07 в утверждённых границах. Нельзя добавлять роль `viewer` или курьерскую учётную запись.

## WF-D01. Главная администратора: управление, а не операционный дашборд

```text
┌────────────────────────────────────────────────────────────────────────┐
│ МедАрхив / Администрирование                       [Профиль]          │
├───────────────────┬────────────────────────────────────────────────────┤
│ Главная           │ УПРАВЛЕНИЕ МЕДАРХИВОМ                             │
│ Пользователи      │ [Пользователи]  [Филиалы / локации]               │
│ Организация       │ [Курьеры]       [Секции и полки]                  │
│ Курьеры           │                                                    │
│ Структура архива  │ [Найти объект]  [Административный аудит]          │
│ Поиск объектов    │                                                    │
│ Аудит             │ Изменения справочников / безопасность — кратко    │
└───────────────────┴────────────────────────────────────────────────────┘
```

Не показывать общую ленту перемещений, рабочие очереди отправлений, приёмку или заявки к исполнению. Карточки — вход в безопасные административные действия, без дублирования всех справочников и форм на главной. При наличии счётчиков их содержание/выборка должны соответствовать UX-05; не придумывать новые KPI.

## WF-D02. Пользователи — единый список

```text
┌────────────────────────────────────────────────────────────────────────┐
│ Администрирование / Пользователи                [+ Добавить]           │
│ [Поиск ФИО / логина] [Роль ▾] [Локация ▾] [Активность ▾]               │
├────────────────────────────────────────────────────────────────────────┤
│ ФИО               Логин        Роль       Локация     Статус          │
│ ...               ...          branch     Филиал ... Активен [Открыть]│
│ ...               ...          admin      —           Активен [Открыть]│
└────────────────────────────────────────────────────────────────────────┘
```

Профиль сотрудника имеет **закрытые поля**: ФИО, неизменяемый логин, роль (`branch`, `central_office`, `archive`, `admin`), организационная привязка и активность. Не включать телефон, email, фотографию, дополнительные контакты. Редактирование **собственного** профиля администратором через эту административную операцию запрещено. Деактивированных пользователей не удалять; фильтр «Активность» показывает историю.

## WF-D03. Карточка пользователя: профиль, доступ, безопасность, история

```text
┌────────────────────────────────────────────────────────────────────────┐
│ ← Пользователи / ФИО                        [Активен / Деактивирован]  │
│ [Профиль] [Полномочия] [Безопасность] [История изменений]              │
├────────────────────────────────────────────────────────────────────────┤
│ ФИО           [__________________________]                            │
│ Логин         неизменяем после создания                                │
│ Роль          [branch | central_office | archive | admin ▾]           │
│ Локация       [Активная совместимая единица ▾]                        │
│                                                                        │
│ [Сохранить допустимые изменения]    [Деактивировать / Активировать]  │
├────────────────────────────────────────────────────────────────────────┤
│ ПОЛНОМОЧИЯ                                                            │
│ card_correct    [Назначить / Отозвать]   [Кто назначил / когда]      │
│ Другие отдельные права — только из утверждённого реестра              │
├────────────────────────────────────────────────────────────────────────┤
│ БЕЗОПАСНОСТЬ                                                          │
│ [Сбросить пароль другого пользователя]                                │
│ [Повторно ввести собственный действующий пароль администратора]       │
├────────────────────────────────────────────────────────────────────────┤
│ ИСТОРИЯ: дата / тип изменения / инициатор / безопасные подробности    │
│ [Тип события ▾] [Период ▾]                                             │
└────────────────────────────────────────────────────────────────────────┘
```

Форма разбита на смысловые секции/вкладки вместо отдельной страницы для каждого изменения. Техническая реализация может использовать отдельные защищённые команды; общий экран не объединяет их в одну небезопасную мутацию.

**Правила карточки:**

- Роль и организационная привязка меняются только у другого сотрудника; новая локация активна и совместима с ролью. Изменение собственной роли и самодеактивация запрещены. Нельзя отключить/понизить последнего активного администратора. При назначении роли `admin` требуется повторное подтверждение пароля инициатора.
- Незавершённые операции не удаляются при деактивации пользователя. Авторство незавершённого shipment-черновика может быть переназначено admin по отдельно утверждённой процедуре после деактивации прежнего автора, но admin не подтверждает handover вместо нового автора.
- `card_correct` не следует из роли автоматически; активный администратор назначает/отзывает его **другому** активному сотруднику. Самоназначение запрещено. Если admin должен получить это право, его назначает другой администратор. Назначения/отзывы пишутся в `AdminSecurityAudit`.
- `card_number_correct` автоматически есть у **каждого активного администратора** и не назначается/отзывается как отдельная галочка. Он разрешает контролируемое изменение **номера карты**, а не обычное редактирование ФИО и даты рождения.
- Сброс пароля другого сотрудника — отдельная операция с повторным вводом собственного действующего пароля администратора и обязательным fail-closed аннулированием всех активных сессий целевой учётной записи. Не выводить текущий пароль сотрудника; не сохранять пароль/хеш/токены в аудите. Сброс собственного пароля этим административным действием запрещён. Одно уведомление о факте последнего успешного сброса — при следующем входе сотрудника, без раскрытия имени администратора.
- История карточки пользователя — фильтр по типу/периоду событий `AdminSecurityAudit`, исходные события неизменяемы. Показывать безопасное представление, не сырой payload.

## WF-D04. Филиалы и организационные единицы

```text
┌────────────────────────────────────────────────────────────────────────┐
│ Администрирование / Организация                 [+ Добавить единицу]   │
│ [Активные] [Неактивные] [Поиск названия]                              │
├────────────────────────────────────────────────────────────────────────┤
│ Название       Тип       Активных сотрудников   Статус    [Открыть]    │
├────────────────────────────────────────────────────────────────────────┤
│ Карточка единицы: [Название] [Статус] [Связанные сотрудники]          │
│ [Переименовать] [Деактивировать / Активировать]                       │
└────────────────────────────────────────────────────────────────────────┘
```

Деактивация запрещена, если остаются активные сотрудники или незавершённые операции. Переименование и повторная активация сохраняют идентификатор, связи и историю. Перевод сотрудника выполняется из его карточки и фиксируется в аудите; не вводить дублирующий «мастер перевода» без необходимости.

## WF-D05. Курьеры — минимальный реестр и карточка

```text
┌────────────────────────────────────────────────────────────────────────┐
│ Администрирование / Курьеры                       [+ Добавить]         │
│ [Поиск ФИО] [Активные / Деактивированные]                             │
├────────────────────────────────────────────────────────────────────────┤
│ ФИО курьера                  Статус                  [Открыть]         │
├────────────────────────────────────────────────────────────────────────┤
│ Карточка: ФИО [____________]  Активен [да/нет]                       │
│ [Сохранить] [Деактивировать / Активировать]                           │
└────────────────────────────────────────────────────────────────────────┘
```

Единственные пользовательские поля курьера — **ФИО и активность** (плюс технический ID). Нет телефона, email, комментария или курьерского аккаунта. ФИО уникально глобально, включая деактивированных; регистр и повторные пробелы нормализуются для проверки. Записи физически не удаляются. Деактивация не переписывает уже назначенных курьеров и снимки ФИО в отправлениях; повторная активация использует ту же запись.

## WF-D06. Структура архива: секции и полки

```text
┌────────────────────────────────────────────────────────────────────────┐
│ Администрирование / Структура архива           [+ Секция / полка]     │
├────────────────────────────────────────────────────────────────────────┤
│ Секция A                                                              │
│    Полка A-01      [Активна]    [Открыть]                              │
│    Полка A-02      [Неактивна]  [Активировать]                         │
│ Секция B                                                              │
│    Полка B-01      [Активна]    [Открыть]                              │
├────────────────────────────────────────────────────────────────────────┤
│ Полка: [Название] [Статус] [Текущее число коробок — только read]     │
│ [Создать] [Переименовать] [Деактивировать / Активировать]             │
└────────────────────────────────────────────────────────────────────────┘
```

Создание/переименование/деактивация/активация полок — только admin. Нельзя деактивировать полку с активным размещением хотя бы одной коробки; интерфейс показывает причину и ссылку на просмотр, **не** кнопку «Переместить коробку» от имени администратора. Коробки перемещает архив через WF-02. История и идентификатор полки сохраняются; физическое удаление запрещено.

## WF-D07. Глобальный поиск и просмотр объектов

```text
┌────────────────────────────────────────────────────────────────────────┐
│ Администрирование / Поиск объектов                                    │
│ [Карты] [Коробки] [Отправления] [Заявки]                              │
│ [Поиск по допустимым критериям выбранного реестра]                    │
├────────────────────────────────────────────────────────────────────────┤
│ Результат → Карточка объекта (глобальный read)                        │
│           → Контекстная история конкретного объекта                   │
│                                                                        │
│ Карта №... [Просмотр] [Исправить номер — особое действие admin]       │
│ Коробка №... [Просмотр] [Списать, только если пустая и допустима]     │
└────────────────────────────────────────────────────────────────────────┘
```

Глобальный просмотр admin — отдельно от операционного поиска по локации. Нет глобального журнала **всех** движений. Карточка объекта и его события доступны по D-07, но кнопки обычных операций не показываются. Контекстная корректировка номера карты (`card_number_correct`) требует **обязательной причины**, глобальной уникальности нового номера и сохраняет старое/новое значение, исполнителя, дату/время в неизменяемой истории. Контекстное списание пустой коробки по P-05 — только если нет карт, открытого логистического цикла, активного отправления или размещения.

**Уточнение:** обычное исправление ФИО/даты рождения (`card_correct`) — отдельное назначаемое право, не даётся роли admin автоматически и не заменяется `card_number_correct`. Нельзя объединять эти два действия в универсальное «Редактировать карту». Отдельные административные корректировки P-07 показываются только при наличии конкретного утверждённого контракта, а не как кнопка «Исправить всё».

## WF-D08. Административный и безопасностный аудит

```text
┌────────────────────────────────────────────────────────────────────────┐
│ Администрирование / Аудит безопасности                               │
│ [Тип события ▾] [Даты ▾] [Субъект ▾] [Результат ▾]                  │
├────────────────────────────────────────────────────────────────────────┤
│ Дата/время     Тип          Инициатор     Цель           [Детали]     │
│ ...                                                                    │
├────────────────────────────────────────────────────────────────────────┤
│ Детали: разрешённые безопасные поля, action, actor, target, reason    │
│ [Переход к карточке объекта — отдельная авторизация]                 │
└────────────────────────────────────────────────────────────────────────┘
```

Читать целевой `AdminSecurityAudit`, а не все `DomainEvent`. Бизнес-историю карт/коробок/отправлений показывать **в карточке соответствующего объекта**, не смешивать с аудитом безопасности. Не рендерить произвольный JSON или значения секретов. Не создавать события неудачных логинов, истечения обычной сессии, отдельных инвалидированных сессий, если они исключены принятыми решениями. Вопросы сроков хранения/правовых ограничений аудита остаются техническими gates, не новой кнопкой UX-07.

## 1. Сквозной wireflow администратора

```text
Административная главная
 ├─ Пользователи → Карточка → Профиль / Полномочия / Сброс пароля / История
 ├─ Организация → Единица → Переименование / Активация / Деактивация
 ├─ Курьеры → Курьер → ФИО / Активность
 ├─ Структура архива → Секция → Полка → Настройка полки
 ├─ Поиск → Карта/Коробка/Отправление/Заявка → Объектная история (read)
 │                                      └→ Узкая отдельная корректировка
 └─ Административный аудит → Событие → Разрешённые детали

НЕТ: admin → Принять / Отправить / Разместить / Исполнить P-09
```

## 2. Проверки ошибок и блокировок

| Состояние | Реакция интерфейса |
|---|---|
| Администратор пытается поменять собственную роль, профиль, отключить себя или сам себе назначить `card_correct` | Запрет до отправки и на сервере; показать точную причину |
| Деактивация/понижение последнего активного admin | Отклонить атомарно, сохранить активного admin |
| Назначение роли admin без повторного подтверждения пароля | Не выполнять |
| Сброс пароля без повторной проверки пароля инициатора или без инвалидации всех сессий цели | Fail-closed: не фиксировать успешный сброс |
| Новая локация несовместима с ролью / деактивирована | Не сохранять привязку |
| Деактивация локации с активными сотрудниками или открытыми процессами | Не выполнять; показать необходимые действия |
| Дубликат ФИО курьера / попытка использовать деактивированного для нового назначения | Запретить; сохранить историю прежних назначений |
| Деактивация полки с размещёнными коробками | Запретить; перенаправить к просмотру и рабочему процессу архивного сотрудника |
| Попытка обычной приёмки/размещения под admin | Не показывать кнопки и отклонять прямой вызов |
| Корректировка номера карты на уже занятый номер | Не выполнять, историю не переписывать |
| Ошибка обязательной записи `AdminSecurityAudit` | Отменить связанную административную мутацию; не показывать ложный успех |

## 3. Предварительный UX review

- **Workflow-first:** вместо восьми разрозненных административных форм — небольшое количество устойчивых реестров с контекстными карточками; «Профиль / Полномочия / Безопасность / История» объединены в карточке пользователя без смешивания серверных команд.
- Нет отдельной роли курьера, viewer, общей операционной ленты, самостоятельного универсального редактора медицинской карты и кнопок операционных действий в административном меню.
- Для UX-08 проверить: находит ли администратор назначение `card_correct` и историю пользователя; понимает ли причину запрета деактивации полки; может ли отдельно отличить глобальный поиск от административного аудита.
- WF-05 завершает **первый проход по четырём ролям**, но не закрывает автоматически весь UX-07: следующая задача — сквозная проверка WF-01…05, исключений, доступности и реальных макетов.

**Статус:** текстовые low-fidelity wireframes; не UI-код, не интерактивный прототип, не формальное утверждение технических gates.
