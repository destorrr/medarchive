# UX-07 / WF-06 — управленческая аналитика, визуальная карта и реестр хранения

Дата: 2026-11-22. Статус: **low-fidelity wireframes v1 / концепция для согласования, не реализация**.

## Исходная концепция владельца продукта

Дашборд — инструмент принятия решений, а не набор декоративных счётчиков «всего карт/коробок/отправлений/пользователей». Руководителю нужно понимать, что поступает, что обработано, где растут очереди, где находятся коробки и как организовано хранение. Ранее предложены три направления: **операционная аналитика**, **интерактивная схема архива**, **табличный реестр хранения**. Последние два должны переключаться без потери фильтров и использовать одну выборку данных.

## Что в репозитории подтверждено, а что требует данных

Основания: `UX-05-dashboard-design.md` (закрыт 2026-11-18), `UX-04-information-architecture-and-navigation.md`, `UX-06-storage-model-design.md`, `PRODUCT-DECISIONS-D-01-D-18.md` (D-12), `src/medarchive/adapters/postgresql/models.py` (проверена модель `ArchiveShelf`: section_name и shelf_name).

- **Утверждено UX-05:** сначала рабочие очереди и разрешённые действия; каждый счётчик объясним и ведёт в тот же фильтр; ролевой scope; отдельно входящие коробки, коробки без размещения, P-09 в работе, извлечённые по заявкам карты.
- **Утверждено D-12:** ёмкость и вместимость полок не инвентаризированы. Проценты заполненности, свободные места и пороги перегрузки **не рассчитывать и не выводить**, пока нет физически подтверждённой ёмкости и единицы её измерения. Иллюстративные 72%, 85%, 94% из прежнего эскиза — не данные МедАрхива.
- **Текущая физическая модель:** подтверждена связка `Секция → Полка → Коробка → Карта`. Полка — размещение **коробки**, не отдельной карты. Уровни **помещение и стеллаж** не подтверждены как самостоятельные объекты PostgreSQL-модели; полная исходная иерархия `Архив → Помещение → Секция → Стеллаж → Полка → Коробка → Карта` сохраняется как **перспективная цель**, не как готовые данные.
- **Ролевые границы:** обычные роли не получают глобальную статистику организации. Admin имеет глобальный read объектов, но UX-05 уже утвердил **административный**, а не операционный дашборд admin. Общий управленческий обзор — предложение отдельного read-only представления, не новая роль и не автоматическое изменение полномочий.
- **Движение разнородно:** филиал/ЦО → архив транспортируют коробки, архив → ЦО по P-09 — отдельные карты. Поступления коробок нельзя вычитать из выдач карт и называть балансом карточного потока. Handover P-09 не равен receipt ЦО; custody меняется по каждой полученной карте.
- **Без глобальной ленты движений:** исторические тренды как агрегаты требуют отдельного подтверждённого источника/контракта; конкретные события остаются в контекстной истории карт/коробок/отправлений. AdminSecurityAudit — отдельный security-реестр.

## WF-M01. Обзор движения и ожидающей работы

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ Аналитика движения: [Период ▾] [Допустимая область ▾]                │
├─────────────────────────────────────────────────────────────────────────┤
│ ТРЕБУЮТ ДЕЙСТВИЯ                                                       │
│ [Входящие коробки ожидают приёмки] [Коробки без размещения]           │
│ [Заявки ЦО: новые / в работе] [Карты P-09 ожидают receipt ЦО]          │
│ Каждая карточка открывает разрешённую очередь с теми же фильтрами    │
├─────────────────────────────────────────────────────────────────────────┤
│ ДВИЖЕНИЕ ЗА ПЕРИОД: ЕДИНИЦЫ ПОДПИСАНЫ ЯВНО                            │
│ Поступило коробок: [N]          Получено ЦО карт: [N]                 │
│ Передано архивом карт P-09: [N]  В пути: [отправления по маршрутам]    │
│ ┌─────────────────────────────────────────────────────────────────────┐│
│ │ Динамика поступлений / выдачи / приёмки за выбранный период         ││
│ │ Разные единицы — отдельные графики / серии с явной подписью          ││
│ └─────────────────────────────────────────────────────────────────────┘│
│ Под каждой метрикой: единица, источник, период, момент актуальности  │
└─────────────────────────────────────────────────────────────────────────┘
```

Сначала — операционные очереди; график ниже, а не вместо рабочего интерфейса. Не создавать декоративные показатели, не обещать SLA или просрочку. Пример про 500 поступивших и 350 обработанных карт за неделю — **только концепция**: для такого сравнения требуется единая единица подсчёта, событийная семантика поступления и завершённой обработки, корректный временной интервал.

### Контракт допустимости метрик

| Показатель | Единица/событие | Статус |
|---|---|---|
| Ожидают приёмки архивом | Непринятые позиции manifest коробок | Есть в UX-05; серверный фильтр |
| Коробки без размещения | Коробки архива без активного BoxPlacement | Есть в UX-05 |
| Новые заявки / заявки в работе | Parent P-09 submitted / submitted+processing | Есть в UX-05 |
| Поступило коробок за период | Уникальные подтверждённые box receipt события за период | Новый исторический агрегат, уточнить timestamp/retries/corrections |
| Архив выдал карты за период | Карты полного manifest единственного P-09 handover | Новый исторический агрегат; не означает получение ЦО |
| ЦО получило карты за период | Уникальные item-level receipt | Новый исторический агрегат, отдельный от handover |
| Динамика роста очереди | Остаток на начало + поступило − закрыто в одинаковых единицах | Гипотеза: методика и данные пока не согласованы |
| Процент загрузки / свободные места | Занято мест/объёма ÷ инвентаризированная физическая ёмкость | **Не показывать по D-12** |

Для каждого исторического агрегата перед UX-10 необходимы формула, источник, временная зона, учёт корректировок и retry, точные события и scope, сопоставление счётчика и drilldown. Невозможно автоматически заменить отсутствие данных нулём.

## WF-M02. Интерактивная схема архива: фактические количества

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ Хранение / [Визуально] [Табличный реестр]                             │
│ [Секция ▾] [Полка ▾] [Размещение ▾]                                   │
├─────────────────────────────────────────────────────────────────────────┤
│ Факты: коробок на полках [N] | без размещения [M]                    │
│ Физическая ёмкость: НЕ ОПРЕДЕЛЕНА (процентов нет)                     │
│                                                                         │
│ [Секция A: N коробок] [Секция B: N коробок] [Секция C: N коробок]    │
│                                                                         │
│ Выбрана секция A                                                       │
│ [Полка A-01: N коробок] [Полка A-02: N коробок]                       │
│                                                                         │
│ Полка A-01 → список коробок → карточка коробки → доступная карта     │
└─────────────────────────────────────────────────────────────────────────┘
```

На текущем этапе навигация реально подтверждённых данных — **Архив → Секция → Полка → Коробка → Карта**; последние переходы только при самостоятельном праве на объект. «Помещение» и «Стеллаж» не изображаются как существующие кликабельные уровни. Цвет различает подтверждённые состояния (например, активная/неактивная полка), но не выдуманную перегрузку. Временные карты, извлечённые по P-09, не отображаются как размещённые на полке.

## WF-M03. Табличный реестр: те же данные и фильтры

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ Хранение / [Визуально] [Табличный реестр]                             │
│ [Секция ▾] [Полка ▾] [Номер коробки _____] [Статус размещения ▾]     │
├─────────────────────────────────────────────────────────────────────────┤
│ Секция   Полка    Коробка     Карт внутри   Размещение               │
│ A        A-01     BX-001      42            На полке                 │
│ A        A-01     BX-002      38            На полке                 │
│ A        A-02     BX-003      45            На полке                 │
│ —        —        BX-004      27            Без размещения           │
├─────────────────────────────────────────────────────────────────────────┤
│ [Карточка коробки]  [Сортировка по подтверждённым полям]              │
│ [Экспорт только при отдельно разрешённом полномочии]                 │
└─────────────────────────────────────────────────────────────────────────┘
```

Строки демонстрационные; **84%, 76%, 90% запрещено отображать как реальные показатели**. Номера карт и ФИО не включать в общую таблицу сверх согласованного scope. Искать номер коробки — по разрешённому реестру; поиск карты по номеру в общем архивном реестре **не считать автоматически утверждённым**: глобальный/обычный поиск карт ограничен согласованными правилами, а номер/телефон разрешены в контексте упаковки. Перспективный поиск расположения по номеру карты требует отдельной проверки разрешённого способа поиска, без раскрытия чужой карты. Фильтрация помещения/стеллажа станет доступной только при введении соответствующих сущностей.

**Единый источник:** обе поверхности получают один серверный набор разрешённых объектов и одинаковые фильтры; таблица может быть постраничной, а суммарные количества схемы — нет. При переключении сохраняются секция, полка, фильтры, выбранный объект и контекст возврата. Экспорт — только после отдельного разрешения и с тем же scope.

## WF-M04. Карточка полки

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ Хранение / Секция A / Полка A-01                                     │
│ Полка активна     Коробок: N     Вместимость: нет данных             │
├─────────────────────────────────────────────────────────────────────────┤
│ Коробка BX-001      Карт: 42       [Открыть]                          │
│ Коробка BX-002      Карт: 38       [Открыть]                          │
│ [Назад к схеме / реестру с прежними фильтрами]                        │
└─────────────────────────────────────────────────────────────────────────┘
```

Полка — средство навигации и поиска. Операции размещения/перемещения выполняет только уполномоченный архивный сотрудник отдельными командами WF-02; admin управляет справочником полок из WF-05, но не перемещает коробки. Карта без активной коробки/placement не может быть показана как объект конкретной полки.

## Перспективная физическая модель и проценты

Сохраняем исходный UX-замысел: **Архив → Помещение → Секция → Стеллаж → Полка → Коробка → Карта**. Для реализации уровней помещений/стеллажей необходимо сначала согласовать и инвентаризировать физическую структуру. Для вычисления загрузки нужен достоверный знаменатель с конкретной единицей: **места под коробки**, **объём** или иной сопоставимый измеритель. Число коробок не является процентом заполнения; число полок не является вместимостью. Красные/жёлтые зоны перегрузки, остаток свободных мест и сортировка по заполненности доступны только после утверждения измерителя и порогов.

## Разделение ролей и места в интерфейсе

- **Филиал:** только собственные очереди WF-01/UX-05, без общего обзора архива.
- **ЦО:** свои заявки/receipt/внешнее хранение WF-03/04, без автоматического доступа ко всем архивным картам.
- **Архив:** схема и табличный реестр собственной архивной области как альтернативные виды раздела «Хранение», с переходами в WF-02 и P-09.
- **Admin:** глобальный объектный read, но согласованная стартовая admin-панель остаётся административной WF-05. Отдельный организационный аналитический dashboard read-only — продуктовая гипотеза; его аудитория и входная точка требуют подтверждения, не создаём новую роль без решения.

## UX-08 и технические критерии

| Сценарий | Проверка |
|---|---|
| Переключение «Визуально / Таблица» | Одинаковые фильтры, scope и итоговые количества |
| Переход «Секция → Полка → Коробка» | Связанная карточка открывается по отдельной авторизации, без потери контекста |
| Ёмкость неизвестна | Нет процентов, красных «перегрузок» и мнимых свободных мест |
| Архив получил часть коробок | В хранение попадают только фактически принятые; приёмка и размещение не смешаны |
| Карта извлечена по заявке ЦО | Не учитывается как лежащая на полке без коробки |
| Исторический график | Правильная единица, событие, момент времени; никакого смешивания handover/receipt |
| Нет данных, ошибка или недостаточно прав | Отдельные безопасные состояния; ноль не подменяет отсутствие источника |
| Экспорт | Не появляется без отдельного полномочия; PII и фильтры не обходятся |

**Статус:** WF-06 сохраняет исходную концепцию как часть UX-07, но не отменяет принятый UX-05/D-12 и не объявляет расширенную управленческую аналитику утверждённой реализацией. До UX-10 нужно решить вопросы объёма физической инвентаризации, возможных уровней «помещение/стеллаж», временных агрегатов и полномочий на обзор всей организации. UX-08 должен проверять дизайн на демонстрационных данных; UI-код, ORM, SQL и миграции в данном этапе не меняются.
