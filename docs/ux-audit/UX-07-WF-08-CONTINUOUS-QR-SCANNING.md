# UX-07 / WF-08 — филиал: непрерывное QR-сканирование карт и наполнение коробок

**Дата:** 2026-11-23. **Статус:** проектный UX-контракт для review владельцем продукта. Код не изменён. Вопрос о полностью автоматическом подтверждении **создания новой** карты выделен отдельно, поскольку текущая PostgreSQL-реализация требует подтверждения.

## 1. Основания и исходный контракт

- `UX-07-WF-01-BRANCH-WIREFRAMES.md`: два равноправных пути «сначала карта» и «сначала коробка», QR или ручной ввод; поиск по ФИО.
- `UX-07-UNIFIED-SCREEN-MAP-AND-NAVIGATION.md`: единые шаблоны карт и коробок, сохранение контекста, роль филиала.
- `src/medarchive/services/postgresql_card_intake.py`: QR v1 — **JSON-объект** с `version:1`, `card_number`, `full_name`, `birth_date` в ISO `YYYY-MM-DD`, необязательный `phone`. Номер обязателен и уникален, ФИО и дата рождения обязательны. По номеру ищется существующая карта; несовпадение ФИО/даты рождения — ошибка, не молчаливое исправление.
- `src/medarchive/templates/postgresql_packing.html`, `src/medarchive/routers/postgresql_packing.py`: текущий UI предлагает текстовое поле QR и кнопку «Проверить QR-код»; существующая карта добавляется сразу, новая сначала проходит `inspect_from_qr` и явное подтверждение `register_from_qr` + `add_card_to_box`. Это **реальное расхождение с желаемым непрерывным UX**, а не готовая функция.
- `docs/plans/2026-09-05-card-identity-qr-design.md`: историческая концепция; использовать актуальный реализованный формат из сервиса как технический baseline, не историческое предположение о формате без образца.

## 2. Главный UX-принцип

**QR-сканирование — постоянно готовый основной канал ввода**, когда сотрудник находится в рабочем разделе «Карты» или в конкретной открытой коробке филиала. Не требуется нажимать «Сканировать QR» перед каждым считыванием. Ручное создание/поиск по ФИО остаётся дополнительным явным действием.

Предпочтительный основной сценарий — физический USB/Bluetooth HID-сканер, эмулирующий ввод с клавиатуры и суффикс Enter. Не требовать установки внешнего ПО, если устройство работает как HID. Веб-камера/мобильная камера — отдельный включаемый режим с явным разрешением камеры и возможностью многократного чтения без повторного открытия, но **не обязательный** путь для основного рабочего места.

### WF-S01 — режим «Карты»: непрерывная регистрация / поиск

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Филиал / Карты                         ● Сканер готов                   │
│ Сканируйте QR с титульного листа карты                                 │
│ [ФИО: ручной поиск]   [Создать вручную]    [Камера: включить]          │
├──────────────────────────────────────────────────────────────────────────┤
│ Последняя операция: Карта №12345 · Уже зарегистрирована                │
│ История текущей рабочей сессии: [Успешно] [Требуют внимания]           │
│                                                                      │
│  Новое считывание → разбор → поиск по номеру → результат               │
│  Затем автоматически готов к следующему считыванию                    │
└──────────────────────────────────────────────────────────────────────────┘
```

- При валидном QR существующая доступная карта показывается в результатах без создания дубликата.
- При валидном QR новой карты — предложить регистрацию с заполненными полями; **вопрос автоматического сохранения без подтверждения открыт, см. §6**.
- Сканирование **не** является ручным поиском по номеру; номер извлекается из структурированного QR, а ручной поиск остаётся только по ФИО.

### WF-S02 — режим «Коробка»: непрерывное наполнение

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Филиал / Коробки / BX-125              ● Сканер готов                  │
│ Сканируйте карту — она будет добавлена в коробку BX-125               │
│ [Найти по ФИО]   [Создать вручную]  [Открыть другую коробку]           │
├──────────────────────────────────────────────────────────────────────────┤
│ В коробке: 24 карты                                                   │
│ Последняя операция: ✓ Карта №12345 добавлена                          │
│                                                                      │
│  QR → валидация → поиск по номеру → регистрация при необходимости     │
│                         → атомарное добавление в BX-125              │
│                                                                      │
│ [Состав коробки] [Последние сканирования] [Ошибки]                    │
└──────────────────────────────────────────────────────────────────────────┘
```

- Текущая коробка — **явно видимый и закреплённый контекст**. При переходе на другую коробку следующий QR относится только к новой коробке. Не направлять считывание в фоновую/ранее открытую коробку.
- Повторное сканирование карты, **уже состоящей в этой коробке**, не создаёт второе membership и не увеличивает счётчик; показать «Уже в коробке» и продолжить.
- Карта в другой активной коробке, недоступная по scope, в отправлении, неактивная или с несовпадающими данными — **блокировать**, не перемещать автоматически. Явный отдельный workflow «Перенести» возможен только по действующим правилам и правам; не превращать повторное сканирование в скрытую перегруппировку.
- Если регистрация новой карты и добавление в коробку — одна подтверждённая операция, они должны выполняться атомарно: не оставлять «полусозданную» карту после ошибки добавления.
- При открытии ручной формы или поиска сохранять контекст BX-125 и возвращаться к режиму готовности сканера после завершения/отмены.

## 3. Как обеспечить сканирование без кнопки

1. В пределах **рабочего режима** «Карты» / «Коробка» слушать ввод от HID-сканера через отдельный буфер и явный признак окончания (обычно Enter/CR/LF, настраиваемый профиль оборудования). Принимать **целый QR**, а не отправлять запрос на каждую клавишу.
2. Не перехватывать набор текста в полях поиска по ФИО, ручного ввода, комментария, фильтрах, модальных диалогах или системных сочетаниях клавиш. Если фокус в форме, сканирование должно быть явно направлено в предназначенное поле либо режим приёма временно приостановлен; не портить введённый текст.
3. **Не считать любой быстрый набор текста сканером.** Отличать устройство/ввод по явно выбранному рабочему режиму, структуре QR v1 и корректному терминатору. Для HID нет надёжного браузерного API, гарантирующего различение физического сканера и клавиатуры; поэтому нужен тест на целевом оборудовании и безопасная обработка обычной клавиатуры.
4. Показывать состояние: «Готов», «Обрабатывается», «Нужна проверка», «Пауза», «Ошибка». При потере соединения с сервером не показывать ложный успех.
5. Во время обработки одного скана не допускать параллельных неупорядоченных изменений состава коробки. Очередь считываний с ограниченным размером, последовательной обработкой и уникальным `scan_id`/`idempotency_key` на действие; при перегрузке — явное «Подождите», а не молчаливая потеря скана.
6. После успешного ответа возвращать готовность автоматически; использовать короткий визуальный сигнал и необязательный звук, без обязательного клика «ОК». Звук не единственный способ сообщить результат.
7. При конфликте не блокировать весь интерфейс навсегда: показывать запись в «Требуют внимания», позволять продолжить сканирование остальных карт; **но** при подтверждении новой карты не связывать ответ с другим сканом.
8. При смене страницы/роли/коробки, открытии диалога или уходе с рабочего экрана сбрасывать незавершённый буфер; запрещать скрытое добавление в старый объект.

## 4. Серверный поток и гарантия безопасности

```text
HID QR + Enter
  → локальный буфер (полный payload)
  → проверка формата JSON v1
  → серверная проверка actor / branch scope / card_number
  ├─ найдено, доступна
  │    ├─ режим Карты: показать найденную карту
  │    └─ режим Коробка: add_card_to_box (идемпотентно)
  ├─ не найдена
  │    ├─ режим Карты: регистрация (см. решение §6)
  │    └─ режим Коробка: регистрация + add_card_to_box (атомарно)
  └─ конфликт/невалидный QR
       → сообщение с безопасной причиной, без мутации
  → обновление списка / счётчика / состояния сканера
```

**Никакой фронтенд-автоматизм не заменяет серверные проверки** уникальности номера, согласованности ФИО/ДР, активной роли и локации, принадлежности карте/коробке, shipment/custody, одного активного membership и истории. Считывание не может само исправлять ФИО, дату рождения, телефон или номер существующей карты.

## 5. Ошибки и обратная связь

| Событие | Поведение UI | Мутация |
|---|---|---|
| Валидный QR, карта уже в текущей коробке | «Уже в коробке», нейтральный сигнал | Нет |
| Валидный QR, карта доступна | «Добавлена в BX-125», обновить количество | Только подтверждённое добавление |
| Новая карта | Данные из QR и результат согласно §6 | Не создавать без принятого правила |
| Номер карты найден, ФИО/ДР не совпадают | «Несоответствие данных карты», требуется разбор | Нет |
| Карта в другой коробке/отправлении | «Нельзя добавить: карта недоступна» с допустимым контекстом | Нет |
| Неподдерживаемый JSON/версия/дата | «QR не распознан», предложить повторить/ручной ввод | Нет |
| Один и тот же QR считан дважды | Не дублировать операцию; нейтральный повтор | Нет второй мутации |
| Сервер не ответил/тайм-аут | «Результат не подтверждён», сверить по `scan_id` перед повтором | Не обещать успех |
| Смена коробки во время обработки | Зафиксировать цель команды на сервере и запретить её незаметную подмену | Нет добавления в другую коробку |
| Сканирование при вводе ФИО/в диалоге | Не перехватывать обычный ввод | Нет |
| Очень быстрый поток QR | Контролируемая очередь, видимый прогресс/ошибки | Последовательная обработка |

## 6. Единственное продуктовое решение, требующее подтверждения

**Существующий PostgreSQL-сервис специально разделяет `inspect_from_qr` и `register_from_qr`, чтобы новая карта создавалась только после подтверждения оператора.** Пользователь теперь предлагает бескнопочный поток. Это **не** следует молча объявлять уже согласованным изменением бизнес-правила.

Рекомендуемый режим для UX-08:

- **Обычный поток:** если QR валиден, номер не занят, роль/scope и все инварианты соблюдены, **автоматически зарегистрировать новую карту**; в режиме коробки — атомарно добавить её туда. Отдельное подтверждение каждого штатного скана не требуется.
- **Исключения:** совпадения ФИО с другими номерами, расхождения данных по номеру, конфликты коробок, ошибки формата или недостаток прав → **не создавать/не переносить молча**, показать разбор оператору. При совпадении ФИО и ином номере — показать возможные совпадения и потребовать подтверждение отдельной карты согласно уже принятому правилу.
- **Альтернатива до подтверждения:** сохранение текущего обязательного подтверждения новой карты, но с постоянно готовым сканером и быстрым inline-review. Такой вариант снижает скорость поточной регистрации.
- После принятия решения обновить UX-06/DB-контракт, API и тестовые инварианты **на этапе реализации**, не сейчас.

## 7. UX-08 acceptance scenarios

1. 30 последовательных QR в коробке без нажатия кнопки сканирования → 30 независимых обработанных результатов, без потерянных/дублированных записей.
2. 30 QR в разделе «Карты» → поиск существующих или регистрация новых согласно принятому правилу; **никакого добавления в коробку**.
3. Одна и та же карта сканируется повторно → не появляется второе membership.
4. Смена коробки BX-125→BX-126 → новые сканы идут только в BX-126; ожидающие запросы не переадресуются.
5. Открытый ручной поиск по ФИО → ввод текста не воспринимается как QR; после закрытия режим сканера восстановлен.
6. Скан карты с совпадающим ФИО и другим номером → оператор видит проверку дубля; нет скрытого создания.
7. Скан QR с несовпадающим номером/ФИО/ДР → блок, без автоматической корректировки существующей карты.
8. Ошибка сети/повтор запроса → безопасный idempotent retry и понятный статус.
9. Быстрый поток при медленном сервере → ограниченная очередь, никакого тихого пропуска.
10. Проверка на реальном USB HID-сканере и типовых настройках Enter/CRLF; также клавиатурная доступность и камера по отдельному сценарию.

## 8. Влияние на ранее подготовленные WF

- WF-B01/B02/B03: заменить «кнопка сканирования как обязательный шаг» на **всегда готовый сканер в активном рабочем контексте**; кнопка «Камера» остаётся опциональной.
- WF-07 и архивная перегруппировка X07 не затрагиваются: непрерывный QR-режим **филиала** не предоставляет архиву скрытое изменение membership.
- В визуальных low-fi компоновках добавить явный статус сканера и результаты последних операций.
- Нужна проверка на UX-08 с реальным HID-устройством; статический макет не доказывает, что считыватель будет работать без фокуса и без нажатия кнопок.

**Статус:** предложен UX-процесс; одна развилка (автоматическое создание новой карты без подтверждения) требует решения владельца. Исходники и тесты не менялись.
