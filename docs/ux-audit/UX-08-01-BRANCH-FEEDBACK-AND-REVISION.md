# UX-08 — замечания владельца продукта к прототипу 01 и план переработки

**Дата:** 2026-11-23. **Статус:** feedback принят к переработке; UX-07 не переоткрывается, UX-08 продолжается. Основание — восемь замечаний владельца продукта после просмотра `prototypes/UX-08-01-BRANCH-QR-FLOW.html`.

## 1. Проверка замечаний по фактическому прототипу

| № | Замечание | Фактическое состояние | UX-08 действие |
|---|---|---|---|
| 1 | Несглаженный шрифт | Используется системный стек `system-ui`; межплатформенный рендеринг не проверялся | Подобрать типографику, проверить Windows/browser, не обещать принудительное системное сглаживание |
| 2 | Непонятная «Пауза сканирования» | `pause` блокирует `scan()`, но ручные действия и навигация остаются доступны; назначение не объяснено | Убрать кнопку из основного рабочего сценария; не вводить фиктивную глобальную блокировку |
| 3 | Нет нормализации ФИО | При ручном создании сохраняется `trim()`; `norm()` используется только для сравнения, не отображения | Нормализовать пробелы и регистр компонентов ФИО, сохранять читаемое «Петров Сидор Иванович»; учесть составные фамилии и не менять бездумно иностранные имена |
| 4 | Поиск по ФИО не позволяет добавить карту | `search-results` формируется как текстовая строка, не как интерактивные результаты | В открытой коробке показывать карточки совпадений с действием «Добавить в BX-…», доступность/конфликт и запрет повторного membership; в режиме без коробки — «Открыть карту» |
| 5 | Дублирование сканов при отдельной регистрации | Первый экран — «Карты», коробка вторична; отдельная регистрация не добавляет карту в коробку | **Основной вход: коробки → создать/открыть → непрерывное сканирование**, регистрация вне коробки — вторичный путь без удаления возможности |
| 6 | Не видно создания и удаления коробок | В HTML две заранее заданные `BX-125`/`BX-126`, создание/списание отсутствуют | Реализовать в прототипе «Создать коробку» и «Списать пустую коробку»; P-05 — не hard delete, не допускается при membership, активном placement, shipment, BoxCycle и других запретах |
| 7 | «Требуют внимания» непонятно | Отдельная вкладка `issues`, конфликт оторван от контекста сканирования | Показывать inline карточку исключения в текущем контексте; не делать из этого отдельный главный раздел |
| 8 | Видимый пример JSON | `scan-input` содержит JSON placeholder и требует Enter | Скрыть технический формат в обычном интерфейсе; оставить отдельный учебный режим/помощник с тестовым QR. Не выдавать скрытое поле за уже работающий HID без фокуса |

## 2. Новый основной маршрут филиала

```text
Коробки → Создать / открыть коробку
       → Непрерывное QR-сканирование
       → Найти существующую карту ИЛИ автоматически создать новую без конфликта
       → Атомарно добавить в открытую коробку
       → Проверить состав / дополнить поиском по ФИО или вручную
       → Подготовить коробки к отправлению
       → Оформить draft отправления → курьер → передать в архив
```

**Вторичный маршрут:** «Карты» → регистрация/поиск/просмотр без обязательной коробки. Не удалять этот процесс и не менять бизнес-правило WF-08; лишь понизить его приоритет в навигации.

## 3. Поведение поиска в коробке

- Только ФИО, частичный ввод, регистронезависимость и е/ё, задержка после ввода, сортировка по алфавиту ФИО.
- Результат показывает ФИО, номер карты, дату рождения и телефон для уполномоченного просмотра.
- Для доступной карты вне коробки — «Добавить в текущую коробку»; для карты уже в текущей — «Уже в коробке»; для карты в другой коробке/отправлении/недоступном scope — объяснение запрета, без скрытого переноса.
- Если ничего не найдено — предложить создать карту вручную в контексте коробки и добавить её одной операцией.
- Клавиатурная навигация, aria-live и восстановление фокуса на сканировании после завершения ручной операции.

## 4. Конфликты и сканирование

- Исключения не теряются: возможный дубль ФИО требует подтверждения отдельной карты; совпадение номера при конфликте ФИО/ДР блокирует создание.
- Inline конфликт не должен мешать следующему штатному скану и не должен автоматически подтверждаться им.
- Убрать кнопку «Пауза сканирования» из основной панели; если режим временного отключения сканера будет нужен по результатам тестирования оборудования, проектировать отдельно.
- Не показывать сырой QR JSON пациентского формата в UI; для тестов использовать только учебные данные.
- Реальный HID без фокуса, CR/LF, кириллица и скорость сканирования остаются незакрытым UX-08 hardware gate.

## 5. Приоритет следующей версии

1. Сделать стартовым экраном список/открытие коробок, создание коробки и P-05 списание пустой.
2. Сделать интерактивный поиск по ФИО с добавлением в текущую коробку.
3. Упростить сканирующую панель, убрать «Паузу», JSON placeholder и отдельный пункт «Требуют внимания».
4. Нормализовать ФИО при ручном создании и в учебном QR.
5. Встроить оформление отправления коробок в архив в следующий прототип.
6. Проверить реальную читаемость шрифтов и responsive/keyboard UX.

**Важно:** замечания относятся к UX-08 прототипу. Никаких изменений production-кода, БД, ORM, миграций или тестов без отдельного разрешения.
