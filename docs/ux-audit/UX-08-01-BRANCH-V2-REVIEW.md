## Исправления по восьми замечаниям

| № | Изменение v2 | Что проверить |
|---|---|---|
| 1 | Типографика: Segoe UI, системные fallback, antialiasing где поддерживается | Реальное качество сглаживания зависит от ОС/браузера |
| 2 | Удалена «Пауза сканирования» | Нет ложного ожидания остановки остальных действий |
| 3 | ФИО при ручном создании приводится к заглавным начальным буквам, убираются лишние пробелы | «Петров сидор Иванович» → «Петров Сидор Иванович»; сложные имена проверить отдельно |
| 4 | Результаты поиска по ФИО стали интерактивными | «Добавить в BX-…» доступно только для карты без коробки; карта в другой коробке блокируется |
| 5 | Стартовый раздел — «Коробки»; отдельный реестр карт вторичен | Не требуется двойное сканирование |
| 6 | Создание коробки и «Списать пустую» | В v2 только учебная имитация P-05: физическое удаление из локальной Map не означает разрешённое удаление записи в БД |
| 7 | Удалена вкладка «Требуют внимания» | Возможный дубль ФИО показывается inline в открытой коробке |
| 8 | Убран JSON placeholder из основного интерфейса | Сырой JSON виден только в явно раскрываемом **учебном** режиме |

## Дополнительно: отправление коробок

Добавлен простой прототип «Отправления»: выбрать одну/несколько непустых свободных коробок, активного учебного курьера, создать черновик, отдельным действием подтвердить передачу. Коробки черновика/переданные блокируются от наполнения. Это **упрощённая демонстрация**, без реальной модели автора, единственного draft, администратора, concurrency, audit trail и courier-directory backend; эти ограничения нельзя считать проверенными.

## Быстрая ручная проверка

1. Открыть HTML локально, нажать «Создать коробку», затем «Сканировать учебную карту» несколько раз.
2. Создать вторую коробку. Попробовать найти по ФИО уже созданную карту: если она находится в первой коробке, перенос должен быть запрещён.
3. В открытой второй коробке создать вручную новую карту с ФИО «Петров сидор Иванович»; проверить нормализованное отображение.
4. В первой коробке выполнить поиск по части ФИО и проверить действие добавления **свободной** карты; для демонстрации свободных карт потребуется отдельный seed/доработка, поскольку v2 создаёт карты сразу внутри коробки.
5. Попробовать создать карту с повторным ФИО и новым номером: увидеть inline-предупреждение и явное подтверждение.
6. Списать пустую свободную коробку; убедиться, что непустая или участвующая в отправлении недоступна для списания.
7. Оформить draft из непустых коробок, выбрать курьера, передать; убедиться, что состав переданных коробок нельзя изменять.
8. На узком экране проверить отсутствие горизонтального переполнения.

## Ограничения и следующие улучшения

- **Не проверен реальный HID без фокуса.** v2 демонстрирует поток через кнопку учебного сканирования или отдельно раскрываемое поле JSON + Enter. Нельзя утверждать, что это уже рабочий бескнопочный HID-интерфейс.
- Нет сервера, PostgreSQL, сохранения, авторизации, проверок реальных прав, атомарных транзакций, журналов событий или многопользовательских конфликтов.
- P-05 в демонстрации удаляет коробку из памяти вкладки, но **реальная бизнес-операция — списание с сохранением истории**, не hard delete. В следующем проходе полезно моделировать archived/writeoff статус и историю даже в локальном состоянии.
- Поиск по ФИО интерактивен, но v2 не создаёт учебных карт вне коробки; для полноценной проверки «найти свободную и добавить» нужен отдельный seed/demo-action или сценарий регистрации вне коробки.
- Кнопка «Сканировать учебную карту» — только демонстрационный способ без настоящего устройства, не предлагаемое действие в production.
- Нормализация ФИО в прототипе упрощённая; в реализации требуется единая серверная политика и проверка редких фамилий/имён.
- Приоритет следующего прохода: тестовый набор свободных карт, имитация P-05 без удаления из локального журнала, проверка полной последовательности филиал → коробки → draft → handover, затем реальный HID и клавиатурная доступность.

**Статус:** UX-08 продолжается; ни код приложения, ни ORM, API, миграции, тесты или CI не менялись.
