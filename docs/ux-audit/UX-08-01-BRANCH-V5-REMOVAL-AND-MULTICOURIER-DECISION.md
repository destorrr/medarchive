# UX-08 — филиал v5: исправление состава коробки и несколько курьеров

**Дата:** 2026-11-23. UX-08 в работе.

## 1. Убрать карту из коробки — согласованная операция

В `UX-07-WF-01-BRANCH-WIREFRAMES.md` уже показано действие «Удалить из коробки». `UX-06-INVARIANTS-DB-TEST-MATRIX.md` DB-56 прямо называет `box_remove_card` и закрытие BoxCycle при удалении последней карты. Поэтому **не требуется новое согласование** для обычного удаления ошибочно упакованной карты из свободной коробки филиала.

Подготовлен автономный локальный HTML v5: в составе открытой коробки у каждой карты есть «Убрать из коробки» с подтверждением; карта сохраняется в реестре без коробки и может быть добавлена в другую через QR/поиск. В коробке в черновике или переданной курьеру действие заблокировано. Локальная имитация не равна DB-операции: при реальной реализации нужны атомарные membership/BoxCycle/event и запреты активных отправлений. **v5 доступна пользователю как загружаемый HTML, пока не синхронизирована с GitHub.**

## 2. Несколько курьеров до передачи — открытое противоречие

Пользователь описал выбор первой группы коробок для первого курьера, затем второй группы для второго курьера **до передачи первой группы**.

Сейчас `UX-07-WF-01-BRANCH-WIREFRAMES.md` и DB-34 требуют **не более одного незавершённого draft у автора**. Кроме того, обычное отправление имеет **одного** курьера и один manifest. Два параллельных отправления в draft для одного сотрудника нарушат DB-34. Одно отправление с двумя курьерами нарушит модель courier shipment.

**Не внедрять молча ни второй draft, ни двух курьеров в один shipment.** Требуется одно целевое решение:
- изменить DB-34 и разрешить несколько черновиков у одного автора с отдельным курьером и manifest для каждого; либо
- сохранить DB-34, предложив последовательное оформление и передачу первого отправления перед вторым.

Рекомендуемый продуктовый вариант — несколько независимых черновиков, если пользователь подтвердит пересмотр ранее согласованного ограничения. Это отдельная точечная корректировка бизнес-правила, не повторный аудит UX-07.

## 3. Статус

HTML v5: добавлено «Убрать из коробки»; JavaScript syntax проверен `node --check`, полноценный браузерный e2e-тест не выполнялся. Многокурьерный draft в v5 **не реализован**, до решения о DB-34. Production код, API, ORM, SQL, миграции, тесты не менялись.
