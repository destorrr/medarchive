# UX-08-06 — P-09 и состав коробок

Статический аудит 2026-11-25. Источники: prototypes/UX-08-03-ARCHIVE-INTERACTIVE-V6.html, prototypes/UX-08-02-CO-APPROVED-V7.html, UX-07-WF-03-P09-CO-ARCHIVE-WIREFRAMES.md, UX-07-DETAILED-ARCHIVE-RECEIPT-REGROUP-P09-STATES.md.

| ID | Наблюдение | Требуемая проверка/исправление |
|---|---|---|
| P09-01 | start() меняет item.result, не b.cards/count | Извлечённые карты исключаются из фактического состава, сохраняется исходная коробка и ответственность архива |
| P09-02 | setResult() меняет только result, причина исключения не сохраняется в событии | Возврат при исключении, повторное извлечение при фактическом обнаружении, причина и история; not_found не считать подтверждённым физическим размещением |
| P09-03 | cancelReq() меняет status/phase/shipment, не восстанавливает membership и не сохраняет причину | Атомарная отмена до handover с возвратом extracted и сохранением причины; после handover запрещена |
| P09-04 | repack() блокирует любой requestId, без проверки завершённости | Блокировать только действующие ограничения; после отмены/завершения проверить доступность по фактическому состоянию |
| P09-05 | reportTableRows() ищет по c.id и c.name | Убрать ручной поиск по номеру карты из общего реестра; сверить разрешённые критерии с WF-06 |
| P09-06 | CO receive() обновляет выбранные позиции и завершает после всех отправленных | Базовая семантика соответствует; независимые демо не доказывают сквозной custody, атомарность и защиту от повторов |

Не изменять утверждённые HTML. Следующий шаг — отдельный черновик архива с согласованной семантикой membership, проверкой seed и регрессионными сценариями. Не вводить новые бизнес-правила. Браузерные тесты не проводились; исходники приложения не изменены.
