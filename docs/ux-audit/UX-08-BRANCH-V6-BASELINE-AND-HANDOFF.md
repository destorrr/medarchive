## Согласованные рабочие решения филиала

1. Основная навигация: **Коробки** и **Отправления**. Пассивный глобальный реестр «Карты» не нужен в главном меню филиала; отдельные операции с картой не отменены.
2. Основной сценарий: создать/открыть коробку → сканировать QR в постоянно видимом поле, которое возвращает фокус после штатного сканирования → найденную карту добавить или новую автоматически создать и добавить при отсутствии конфликта. Технический JSON не показывать как основной пользовательский интерфейс.
3. Альтернативы в контексте коробки: поиск по частичному ФИО (результат с действием «Добавить»), ручное создание карты с нормализацией отображения ФИО; формы не остаются раскрытыми после успешного завершения.
4. Карта, ошибочно добавленная в свободную коробку, может быть **убрана из коробки без удаления самой карты**. Затем карта добавляется в другую коробку QR или поиском. Запрет на изменение состава коробки в черновике/после передачи. Изменения membership/BoxCycle и события должны быть атомарны при реализации.
5. Пустую свободную коробку можно списать P-05, но **нельзя физически удалить из БД**; история сохраняется.
6. В отправлениях сотрудник отмечает непустые свободные коробки → выбирает активного курьера → **«Назначить курьера»** → выбирает другую группу и другого курьера → **«Создать черновики»**. Каждая группа становится отдельным нумерованным draft с одним курьером и непересекающимся составом коробок.
7. Для каждого draft отдельно: **«Обновить черновик»**, **«Отменить черновик»**, **«Передать курьеру»**. Передача создаёт самостоятельное отправление с номером и курьером. Другие draft не требуют предварительной передачи.
8. Несколько незавершённых черновиков одного автора **разрешены**: прежний запрет «не более одного» отменён точечным решением UX-08. См. `UX-07-WF-01-BRANCH-WIREFRAMES.md` (добавленное уточнение) и DB-34 в `UX-06-INVARIANTS-DB-TEST-MATRIX.md`. Нельзя включить коробку в два активных draft.
9. Минимализм: компактная панель QR, понятная визуальная иерархия, одинаковые размеры однотипных кнопок, отсутствие общего потока «История действий», отсутствие повторяющихся сообщений после переходов и избыточных заголовков. История отдельных объектов при этом остаётся обязательной частью доменной модели.

## Проверка соответствия и ограничения

- Исходный HTML v6 прочитан из ранее выданного пользователю файла и сохранён в репозитории. В нём присутствуют элементы «Назначить курьера», «Создать черновики», «Обновить черновик», «Отменить черновик», «Передать курьеру», «Убрать из коробки» и поле QR.
- Владелец продукта **визуально просмотрел v6** и не высказал новых замечаний на данный момент. Это не равно тестированию всех исключительных сценариев.
- Автономный HTML работает на учебном состоянии без PostgreSQL, серверной авторизации, транзакций, журналов аудита и настоящей интеграции с аппаратным HID-сканером. Утверждать прохождение hardware/DB/e2e-тестов нельзя.
- QR v1 — данные внешней МИС; реальные ФИО, даты рождения и телефоны не использовать для демонстрации.
- Не изменены production-приложение, ORM, API, SQL, миграции, тесты и CI.
- UX-07 был ранее утверждён; точечное изменение правила черновиков задокументировано, остальные согласованные роли и маршруты сохраняются.
