**Начало:** 2026-11-23. **Основание:** владелец продукта утвердил UX-07. **Статус:** UX-08 product baseline согласован; технические exit gates открыты. UX-07 закрыт по UX design exit. Производственная реализация **не разрешена**.

## Прототип 01 — филиал: непрерывный QR

[Открыть утверждённый прототип филиала v8](prototypes/UX-08-01-BRANCH-APPROVED-V8.html)

Одностраничный автономный HTML/CSS/JS прототип. Запускается локально в браузере после скачивания файла; GitHub просмотр исходника не исполняет HTML. **Нет** подключения к PostgreSQL/API и нет сохранения на сервере. Не использовать реальные персональные данные пациентов.

### Что можно попробовать

1. Раздел **Карты** → «Подставить учебный QR» → Enter в QR-поле. Новая карта автоматически создаётся в памяти страницы, без подтверждения; повторный QR находит существующую.
2. Раздел **Коробка** → выбрать BX-125 → несколько учебных QR → Enter. Карты добавляются в видимую коробку; повтор в той же коробке не создаёт дубль.
3. Переключиться на BX-126 и попробовать QR уже упакованной карты: прототип покажет конфликт, не переместит карту.
4. Сканировать два QR с одинаковым ФИО и разными номерами: второй требует проверки в разделе «Требуют внимания», подтверждение отдельной карты — явное.
5. Сканировать одинаковый номер с отличающейся датой рождения/ФИО: блокировка.
6. Открыть ручной ввод/поиск ФИО: они работают как альтернативные способы, не подменяют QR.
7. Пауза/возобновление сканирования, мобильная ширина.

### Ограничения, которые нельзя выдавать за выполненные тесты

- **HID ввод** демонстрируется через обычное поле QR с Enter. **Глобальный приём сканов без фокуса ещё не реализован**: у браузера нет надёжного признака, что последовательность клавиш пришла именно от HID-сканера. Реальное оборудование, раскладки, Enter/CRLF и восстановление фокуса должны проверяться отдельно.
- Обработка синхронная, очередь демонстрационная. Нет настоящей конкурентной нагрузки, сети, транзакций, DB idempotency ledger, разграничения доступа и реальной атомарности; поведение имитируется локальным состоянием.
- В прототипе совпадения по ФИО проверяются по точному нормализованному ФИО. Полнота алгоритма потенциальных дублей — задача отдельного контракта и тестов.
- Демонстрационные карты создаются только в памяти вкладки, после обновления страницы пропадают.
- Никаких реальных пациентов, логов PII или внешних отправлений.

## Exit criteria UX-08

- Сценарии каждой роли можно пройти без устного объяснения.
- Навигация сохраняет объектный контекст, права и ограничения не подменяются фиктивными операциями.
- Проверены состояния success, duplicate, conflict, empty, loading, error и keyboard focus.
- Для QR проведён **отдельный тест на целевом HID-сканере** с валидным тестовым JSON и безопасным окружением, прежде чем считать бескнопочный поток подтверждённым.
- Responsive/keyboard accessibility проверены, результаты и ограничения задокументированы.
- DB-69/multi-source repack не реализуется в прототипе как одна атомарная команда без разрешения контрактного расхождения.

**UX-08 — прототипирование, не UX-10.** Ни приложение, ни ORM, ни API, ни миграции, ни тесты проекта не меняются.
