# UX-09.4F — external custody mapping
2026-11-25. Проектирование. Sources: PRODUCT-DECISIONS-D-01-D-18 D-05, UX-07-WF-04 C08/C09, UX-06-TECHNICAL-DATA-MODEL, src/medarchive/services/postgresql_card_custody.py, routers/postgresql_central_office.py.
External custody is not shipment/request/route; balance remains CO. Existing states available, at_court, at_insurance, at_external_organization. Do not overload custody_status with transport custodian. Type and organization required; comment optional; server dates/actor. No act, SLA, due date, external responsible, courier or box assignment.

Existing event IDs verified: card.external_custody_started and card.external_custody_returned. Existing service locks Card, checks actor active central_office, location.kind, status, membership and ShipmentCard draft/in_transit. Existing actor read not FOR UPDATE, location kind alone not proof of target membership scope; target protected command must lock/recheck principal/membership and active location, enforce canonical scope, check target ShipmentBox/membership and all active shipment states including partially_received where applicable. Check active writeoff/reservation conflicts against approved contracts before implementation; do not invent new rights. Current return redirect says returned to CO balance although balance never changed; propose wording "Карта возвращена из внешнего хранения". No auto removal from box: explicit unpack first. No external card in packing selection or direct add/dispatch command. Other roles including admin cannot mark/return by role. 
Atomic state/event/ledger, command_id replay under current access, no duplicate events; concurrency mark vs packing/writeoff/return and deactivation. History event payload projection not wholesale serialization; no PHI in telemetry. External registry is a specific authorized card-level list, not generic shipment queue; scope before counts/pagination. Exact field limits and HTTP contracts pending.
Tests: all 3 types, blank org/invalid type, optional comment, wrong role/location, inactive/written-off card, packed/in-transit/reserved conflicts, repeat mark/return, event failure rollback, concurrent mark/pack, return restores eligibility only after general checks, no new shipment or location change, history across multiple external cycles, direct URL scope.
