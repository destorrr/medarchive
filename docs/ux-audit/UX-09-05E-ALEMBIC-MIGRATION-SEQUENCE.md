## Deployment gap
env.py currently reads MEDARCHIVE_DATABASE_URL with local default, target_metadata=None; alembic.ini also contains local development URL. No separate migration credential or explicit owner context in inspected env.py. Target: mandatory MEDARCHIVE_MIGRATION_DATABASE_URL, verify session_user/current_user and allowed owner membership, controlled SET ROLE, no runtime fallback; offline SQL generation separate from execution and not proof of ACL. No secrets in logs. Keep explicit reviewed DDL; metadata comparison may supplement but not replace trigger/function/ACL review.
## Proposed revision groups (labels, not allocated revision IDs)
| Group | Scope | Exit gate |
|---|---|---|
| E0 preflight, outside revisions | baseline commit, head, PG16, catalog/ACL, row counts and conflicts, backup/restore rehearsal if existing data; provision owner/migrator/runtime outside Alembic | classify empty/disposable vs retained PG data; stop on unknown or incompatible data |
| E1 foundation | ownership/default privileges, API namespace, permissions/session foundation, command ledger, admin audit, typed event extensions | ACL tests, no public execute, existing auth still works until coordinated switch |
| E2 additive storage/request schema | sections, request items, writeoff requests, receipt/discrepancy facts, nullable transitional links and fields | schema tests, no fabricated history; final contracts for affected fields required |
| E3 reconciliation | deterministic mapping only if retained PG rows exist; single old request maps to one parent/item where facts support it; verify manifests/cycles/placements, viewer and courier conflicts | counts and referential checks; unresolved rows stop migration; empty DB no-op |
| E4 coupled workflow cutover | replace card manifest FK, shipment/receipt/request guards and status checks together; route-specific manifests, P09 reservations, storage guards, custody | atomic compatible DDL/data transition, no unguarded committed state; no old app writes during switch |
| E5 protected commands | deploy command families and typed events, per-family API/service conversion and tests | exact signatures, lock graph, correction outcomes and permissions resolved for each family |
| E6 hardening | validate constraints/indexes, revoke direct runtime DML after all writers migrated; negative ACL and concurrency tests | no bypass via ORM/jobs/auth/bootstrap, all workflows pass |
| E7 contract/retirement | remove obsolete columns/guards and active card_placements path only after dependency/history verification; remove SQLite runtime in coordinated release | clean install, upgrade, restore, no legacy imports; retained historical facts accessible |
Groups may split into multiple revisions; final IDs assigned at implementation, linear down_revision links, no rewriting 0001–0011. E4 must be a coherent transaction or explicitly proven safe substeps. E5 is coordinated code+DDL work, not solely migrations. No public exposure of intermediate incompatible schema; maintenance window/stop writers, not dual-write architecture.
## Two deployment paths
Clean install: provision principals, create empty PG database, upgrade base→head, validate catalog, bootstrap admin through controlled path, run smoke tests. No seed medical data. Existing PG: read-only preflight, classify data, verified backup if retained, stop writers, upgrade from actual supported revision, validate and switch app. Disposable reset only with explicit environment identification and authorization; never infer from no SQLite data. Do not stamp head to bypass DDL. No automatic deletion of old files.
## Rollback
Before commit, transactional DDL rollback where supported. After incompatible committed migration, stop app and use verified restore of pre-upgrade snapshot plus matching application version, or reviewed forward fix. No promise of lossless downgrade for semantic changes; document downgrade limitations and test recovery. No concurrent index creation inside transactional revision without explicit separate plan. Never restore over live DB without authorization. 
## Acceptance
Single head; clean base→head and 0011→head with synthetic representative rows; compare effective catalog, constraints, triggers, functions, ownership/default ACL; test rejected inconsistent legacy rows, rollback on injected failure, no fabricated receipt dates, preserved IDs/history, P09 and ordinary receipts, backup restore. Migration runner must reject runtime credentials and missing migration URL. No actual DDL or tests executed. Open: PG preflight, exact schema/receipt correction, lock graph, command signatures, audit retention. Next 5F deployment verification design.
