2026-11-26. Planning only. Reviewed actual postgresql.yml, pyproject.toml, conftest.py, compose, 5F and 6B.
## Existing gaps
CI triggers push master/docs/target-architecture-spec and PR master, not current audit branch. PG16 service initial medarchive user is superuser; migration, tests and backup use same URL. pytest -q -rs reports skips but does not fail on mandatory skips. Alembic current prints revision, core table query checks presence only. Restore checks two tables only; existing age encryption, retention, plaintext rejection, file mode and shell syntax tests valuable and retained. conftest creates SQLite temp file and mutates environment; replace during I01/I10. Python >=3.11, CI 3.12; dependencies mostly lower bounds, reproducible lock/constraints proposed. Compose persistent volume and public port unsuitable for isolated CI; use disposable service.
## Environments
DEV: local PG16 loopback, separate test DB, synthetic fixtures, no production URLs. CI: ephemeral PG16 per job, unique database per test worker if parallelized, no shared production secrets; provision owner NOLOGIN, migrator/runtime/backup LOGIN via controlled bootstrap. MIGRATION: separate clean and 0011 seeded databases; never stamp past migrations. E2E: real ASGI server on loopback with runtime identity, isolated browser contexts per role, synthetic deterministic fixtures. RECOVERY: separate destination DB/instance, temporary age key, reconstruct versioned ACL/ownership, verify actual restored commands. STAGING: production-like isolated synthetic environment, manual HID and deployment checks. No real patient records in any test environment. Explicit test-only environment and database allowlist plus connection identity checks before destructive fixture cleanup; never infer safety from database name alone.

| J06 concurrency/security | every implementation PR | separate connections, deterministic barriers, both winner orders, replay, negative ACL and escalation |
| J07 browser E2E | every implementation PR | Chromium baseline, separate role contexts, real backend, five prototype flows, keyboard/responsive; additional browser coverage before release |
| J08 recovery | changes to schema/security/backup and release; preferably every implementation PR | actual backup identity, age encrypt/decrypt, retention, wrong key/failure, restore rows/ACL/functions and smoke |
| J09 final PG-only | I10 onward mandatory | no SQLite runtime/import/flags, no obsolete routes, full suite, mandatory skip check |
| J10 manual acceptance | I11 release gate | physical HID 30 scans, supported workstation/browser, staging and recovery evidence |
Use one stable required aggregate check that fails if required jobs fail/cancel/skip or missing reports; conditional jobs explicitly evaluated by package/release manifest. No path filter that bypasses mandatory checks. Workflow triggers on active implementation branch and PR target, workflow_dispatch for controlled reruns; exact branch protection settings require repository authority. No automatic production deployment. Least privilege GITHUB_TOKEN contents:read; untrusted PR code no production secrets, no pull_request_target execution of untrusted checkout. Pin action revisions and dependency resolution in implementation.
