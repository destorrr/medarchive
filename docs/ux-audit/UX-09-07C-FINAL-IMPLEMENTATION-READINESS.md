## 3. Открытые gates, не маскируемые процентом проектирования

DB1: read-only preflight фактической PG16, ревизии, данных, ACL, bootstrap.
DB2: типизированные поля, состояния, справочники причин, события/ledger.
DB3: route-aware custody/reservation; legacy ShipmentCard reconciliation; ordinary vs P-09 receipt.
DB4: закрыть точно затрагиваемые команды DB69 regroup, placement permissions, writeoff/packing.
DB5: lock graph, повтор команд, авторизация, атомарность, concurrency.
DB6: read scopes, поиск, временные зоны, пагинация и метрики.
DB7: clean install + 0011 upgrade, негативные ACL, backup/restore, PG-only regression, AST/import checks.
DB8: хранение/удаление, RPO/RTO, инфраструктура/TLS, внешняя копия, HID/browser и решение о запуске.

Нерешённый DB gate блокирует соответствующий пакет, не обязательно независимую подготовительную работу. Не придумывать новые бизнес-правила вместо имеющихся решений.

3. Только по разрешению создать `feature/ux-implementation` от **закреплённого final design SHA**, если ветка отсутствует. При существующей ветке сначала проверить ancestry/дифф, не перезаписывать.

## 5. Definition of ready / done

**Design READY:** четыре роли и три маршрута прослеживаются до согласованных screen/command/invariant/test IDs; пять прототипов закреплены; спецификации 09.1–09.7B, пакетный план, миграции и rollback описаны; технические пробелы явно маршрутизированы.

**Package DONE:** код + миграции по применимости, транзакции, ACL/ownership, блокировки и idempotency, events/audit/ledger, положительные/отрицательные/конкурентные тесты, реальные PG checks и UI acceptance; CI run и SHA записаны, обязательные skip отсутствуют.

**Production READY:** G0–G4 и все 15 пунктов 07B проверены фактически. Design readiness не означает production readiness.
